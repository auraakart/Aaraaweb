# V5.11.3 — bounded occupancy worker discovery

Authorized continuation of V5.11. Cross-society dueApproved previously read full request rows through the root client. Replace that scan with a fixed SQL capability returning only id, societyId and reviewedByUserId. The existing runner needs only these routing fields; it still calls complete with the discovered society/reviewer, skips a missing reviewer and isolates per-request errors.

## Capability contract

- Integer batches 1–50; the service rejects invalid values before database access. Direct function invocation also returns no rows outside that range.
- APPROVED and currently effective requests only, deterministic effectiveAt/id order, same-society unit/building parents required.
- SQL SECURITY DEFINER with pg_catalog/pg_temp search path, qualified relations, row_security on and PUBLIC execution revoked.
- Discovery remains read-only. This deliberately preserves existing retry semantics: no new claim/lease/status transition is introduced. Concurrent runners may discover the same request; tenant completion's row lock and conditional APPROVED transition permit one successful application.
- No empty tenant scope or tenant-wide enumeration is used. No raw request reason, user, document or occupancy details are returned by the capability.

The additive migration alone does not establish hosted isolation. Before use with a restricted runtime role, independently provision a NOLOGIN/NOBYPASSRLS/non-owner capability owner, only required request/unit/building SELECT columns and reviewed SELECT policies, transfer function ownership, revoke schema CREATE and explicitly grant worker EXECUTE. Do not grant global request-table access to the runtime role. This slice does not activate hosted grants or policies.

## Validation

Eight focused tests cover parameter limits, fixed function invocation, routing projection and per-request runner behavior. Expanded risk selection passes locally with existing and V5.11.2 service floors. One new copied-table FORCE RLS case exercises the migrated function owned by a restricted non-owner role, missing EXECUTE denial, explicit EXECUTE, both-society due discovery, future/terminal/malformed-parent exclusion, hard batch limits and no direct global reads after granting the capability. Existing mutation cases cover concurrent completion and audited rollback.

Exact-candidate protected migration/replay, public migrated workflow, complete restricted-role suite and full API acceptance remain required. This is the scheduled occupancy portion of V5.11.3; broader jobs and private-document/storage acceptance remain open. Main/staging, hosted activation, productionization and physical-device work remain excluded.
