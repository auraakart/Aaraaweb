# V5.14.12 — Society analytics transaction boundaries (candidate)

Baseline: accepted V5.14.11 on develop `e265983d84ac3b8794b2041840ca96fe795b84df` (PR #1580 and documentation PR #1581).

## Scope

Only `ReportsAnalyticsService.experienceFunnel` (four society-filtered aggregate SQL statements) and `ReportsAnalyticsService.operationsDashboard` (three society-filtered aggregate SQL statements) move from `PrismaService.$queryRaw` to the transaction client's `tx.$queryRaw` under `withTenantContext(societyId, ...)`. All original SQL predicates, range validation, aliases, response shapes, privacy statements, and permission/entitlement gates remain in place. Transaction context is in addition to existing explicit society filters, not a substitute.

The platform-wide `platformPortfolioCommandCentre` and independent-home `platformOutcomes` are intentionally **not** changed: their cross-society/global scope is authorized separately and must not be forced into a single society context. Society journey and outcomes metrics are deferred for separately bounded review, including finance aggregation and query-plan measurement.

## Regression plan

The new unit regressions must prove selected-society binding on all seven SQL reads, one transaction per request, no fallthrough to root client, sequential society-switch isolation, validation before DB access, and unmodified platform routes. Existing alias, operations and experience-funnel contracts must remain green. The real migrated PostgreSQL operations test verifies selected-society transaction entry. Root-client fallthrough is tested with isolated unit fakes rather than a Prisma spy, because Prisma's transaction proxy may internally pass through instrumented root methods. Native RLS policies are not activated.

Regenerate `docs/architecture/v5-tenant-access-inventory.json` with `node services/api/scripts/tenant-access-inventory.mjs --write` and synchronize `docs/architecture/V5-TENANT-ACCESS-INVENTORY.md` with `node scripts/sync-tenant-access-summary.mjs --write`; commit only the generator-produced files. Require protected API typecheck, tests and PostgreSQL workflows, repository invariants, Admin/Flutter gates, dependency checks and exact tested-head merge. The temporary source-inventory workflow is branch-only and is removed before PR validation. No RLS deployment, provider integration, device testing, productionization, staging or main changes.
