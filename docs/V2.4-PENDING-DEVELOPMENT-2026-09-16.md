## Narrow code findings for the next UI batch

### Resident Home

`apps/resident/lib/screens/home_screen.dart` already implements the new action-center hierarchy, entitlement-aware sections, loading/error/empty states, and a stateful gate-approval card. The remaining concern is responsive density: quick actions currently force a two-column width calculation for every phone width. The next patch should switch to one column below a validated compact breakpoint and preserve two columns on normal/wide phones.

Acceptance:
- no overflow at compact width or enlarged text;
- minimum touch targets retained;
- SOS remains visually distinct;
- entitlement-hidden actions remain absent;
- no navigation/API behavior changes.

### Guard gate operations

`apps/guard/lib/screens/guard_operations_screen.dart` already exposes explicit waiting/approved/check-in/check-out states. The next patch should make successful transitions immediately legible to a guard without relying on implicit card mutation alone (for example, concise semantic/snackbar confirmation driven by successful controller completion), while retaining offline/idempotent behavior.

Acceptance:
- no duplicate gate operation while busy;
- explicit success feedback after entry/exit/approval refresh transitions;
- denied/cancelled remains visually blocking;
- offline queued state remains clear and retry-safe;
- no weakening of gate assignment requirements.
