# V5.14.25 — API CI fail-fast sequencing

Baseline: V5.14.24 merged to `develop` at `ee1e106728cc34569580f5daeddca30732f6eaff`.

## Root cause
The protected `API validation (full)` job ran clean PostgreSQL migrations and the V5 partner ownership historical replay before static source-inventory validation, API lint and API typechecking. A stale deterministic inventory digest or test-only TypeScript typing error therefore consumed database setup/replay time before failing. This sequence repeatedly prolonged correction and retesting across V5.14.20–V5.14.24.

## Change
Without changing any job dependency, condition, test command, acceptance condition, service container, artifact evidence or required merge gate, order the API job after dependency install and Prisma client generation as:

1. Verify the generated V5 tenant-access inventory, preserving the reviewed-diff enforcement.
2. Lint API and typecheck API.
3. Apply clean PostgreSQL migrations.
4. Run historical partner ownership upgrade/replay.
5. Run the existing auth, PostgreSQL, billing, finance, API, coverage, branding and optional benchmark steps in their original order.

The Prisma schema validation and client generation remain before all of the above. No gate is skipped; this only improves **time to actionable failure** when source inventory or TypeScript is wrong. CI job containers still initialize and dependencies still install, so no unsupported duration or runner-cost savings are claimed.

## Acceptance and safety
The change is confined to `.github/workflows/ci.yml` and this document. Because workflow changes are cross-cutting, all existing protected API, Admin, Flutter, dependency and required-merge checks must pass before merging into `develop`. No release branch, deployment, hosted RLS, external provider, signed artifact or device acceptance is part of this slice.
