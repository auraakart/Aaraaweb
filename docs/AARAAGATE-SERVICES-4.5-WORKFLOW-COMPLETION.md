- Provider sign-in → Field-agent workspace: use the same OTP/session flow, but separately reauthorize the user's verified agent mapping at every API boundary. Own assignments, milestone transitions, service start, immutable booking checklist, explicit pass/fail evidence and completion-review request use existing domain services. - Resident My Bookings: explicitly opened booking-time quality/evidence and completed-service rework review. Expired/absent terms never imply coverage. Reuse existing dispute case/one-open-case constraint; uncertain submission requires a status refresh, with no automatic retry or approval.
- Platform service dispatch: review provider-scoped candidate conflicts and resident requests, require explicit confirmation, and call the existing locked quick-dispatch authority. A lost response requires a server-state refresh; no assignment impersonation or guaranteed availability.
- Resident arrival update: reuse the conservative historical ETA. Show unavailable/stale/sample reasons, refuse live/guaranteed or contradictory contracts, and locally expire displayed estimates without periodic network polling.
- Resident recurring preferences: show active/paused/cancelled plans, explicitly confirm preference changes, inspect matching visit/technician history, and plan one visit through the existing availability, current-price and idempotent booking screen. The plan's location is fixed; the existing plan-book endpoint revalidates current access and eligibility. Existing bookings are unaffected by preference changes. No auto-booking scheduler or recurring charge.
