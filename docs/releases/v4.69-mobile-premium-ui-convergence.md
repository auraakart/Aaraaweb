# V4.69 Mobile Premium UI Convergence

## Scope
Modernizes Resident and Guard Flutter presentation without changing API contracts, authorization, tenant isolation, payment semantics, or state-management behavior.

## Implemented
- Preserved primary brand colors `#0EABBE` and `#05879A`.
- Centralized low-elevation shadows and pill radii in Resident and Guard design tokens.
- Added a shared Resident premium quick-action component and reduced phone shortcut density to a calmer 2-column hierarchy.
- Made resident gate approval's positive action visually dominant while retaining immediate deny access.
- Reworked the billing hero and moved AutoPay configuration below immediate dues.
- Removed redundant `.00` from whole-rupee billing amounts.
- Reduced amenity card elevation and clarified booking language.
- Split Notices into `Action required` and `Latest updates`.
- Collapsed active Guard gate switching behind a secondary disclosure and promoted Delivery, Cab and Walk-in as large operational actions.
- Kept existing 48dp Resident and 56dp Guard minimum interaction targets.

## Non-goals
No backend/API, payment-state, visitor authorization, production integration, or navigation architecture changes.

## Validation
Existing Resident and Guard widget/regression suites remain the release gate, especially large-text accessibility, visitor decision recovery, billing recovery, amenity booking/cancellation recovery, Guard modal lifecycle/watchlist boundaries, and light/dark theme consistency.


## CI delay root-cause closure

- Historical finance trust validation now checks overdue amount visibility, danger-state semantics, payment follow-up, and checkout-policy transparency instead of one exact UI sentence.
- Expensive full validation jobs wait for the fast repository-contract gate, so a contract failure does not consume API/Admin/Flutter runners in parallel.
- Pull-request validation is path-aware: mobile-only changes run Flutter validation while unrelated API/Admin full suites are intentionally skipped. Cross-cutting and unknown runtime changes still default to full validation.
- Required wrapper check names remain unchanged, preserving branch-protection contracts.
