# V5.14.21 — WhatsApp approved-template own-key validation (accepted on develop)

Baseline: merged V5.14.20 on `develop` at `d1cbd361666f8a703d398414cd36a7055c06f745`. This is a bounded source follow-up, not a release or hosted acceptance change.

## Defect
The WhatsApp template dispatcher previously indexed the plain approved-template registry with an input asserted to be a `WhatsAppTemplateKey` at compile time. At runtime a value such as `__proto__` or `constructor` resolves an inherited property from `Object.prototype` rather than an explicitly approved entry. Attempting to iterate the inherited object's absent `requiredParameters` can throw a `TypeError`, instead of returning the existing `BadRequestException` for an unapproved template.

## Remedy and tests
Require a string key that is an own property of `APPROVED_WHATSAPP_TEMPLATES` before dereferencing it. The provider is never called for an unsupported key. Five negative regressions cover `__proto__`, `constructor`, `toString`, an unknown key and an empty key. Existing positive-template and idempotency coverage is preserved.

No public route, database, migration, tenancy, approval semantics, provider configuration or white-label distribution change. No active WhatsApp provider acceptance is implied. Protected CI is required before merge into `develop`.
