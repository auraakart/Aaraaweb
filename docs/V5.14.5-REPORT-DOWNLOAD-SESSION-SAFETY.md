# V5.14.5 — Report download session safety (accepted source)

Baseline: accepted V5.14.4 develop `41c9a0ce9c72a867c11c1e9747cd3316046703d8`. This is an Admin-only session/CSV change; no API, database, tenant grant, permission, report schema, or CSV data contract is changed.

## Root cause and correction

The Reports page downloaded CSV through direct fetch rather than the shared Admin session client. It did not reject a society switch or replaced login while waiting for report bytes, and an expired bearer could not use the existing authorized single-refresh flow.

`downloadAdminBlob` now checks the stored session lineage before the request, after the response and after the blob body resolves. It retries only one 401 using the same login family. The Reports UI retains safe filename handling, row metadata, unchanged routes and export audit behavior. Non-401 errors retain the common Admin error interpretation.

## Tests and acceptance

Five regression cases extend the established Admin session suite: stale society before network, authorized one-time refresh, late login replacement, society replacement mid-stream and non-401 denial without replay. Protected CI [41752286168](https://github.com/auraakart/Aaraaweb/actions/runs/41752286168) passed, including Admin typecheck, session/access regression contracts, SSR/cookie isolation, browser/accessibility, build, API, Flutter, dependency audit and merge gates. PR #1574 merged on develop as `a186cfb4771536c7c7d36ded0e0f59560c14dddc`; tested and merged tree `712842c321ce4ccf135e63dc62787ae93e07dc98` match. The initial failed attempts exposed historical V4.49 and Admin access tests tied to the prior file location; both were updated to require guarded shared transport.
