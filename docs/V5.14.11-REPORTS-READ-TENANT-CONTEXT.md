# V5.14.11 — Reports read tenant-context conversion (accepted on develop)

Baseline: accepted V5.14.10 develop `2066c6eb952c0fa0a17e23b53a7ee9234a490847`. This slice changes only Reports read-service DB calls, their unit tests, and evidence. Report CSV exports were converted in V5.14.9; analytics-wide and platform portfolio SQL remain separate.

## Tenant transaction and authorization boundary

All society-scoped report read paths—summary, comparison summaries, access feed, helpdesk feed, maintenance feed, security event raw SQL, and audit feed—execute through `PrismaService.withTenantContext(societyId, async(tx) => ...)` and the supplied transaction client. This establishes the transaction-local PostgreSQL society setting while retaining each query's explicit society predicates, role/permission gates in the controller, response fields, date/window limits, bounded pagination, stable ordering and finance redaction. Maintenance drilldown also requires the linked Unit and Building to belong to the selected society.

No database RLS policy is activated by this patch. The existing service/guard predicates remain required because the hosted role/grant and policy matrix (#212) has not been deployed. Reporting analytics (society and platform), notifications, workforce services and independent partner artifacts remain outside this bounded slice.

## Tests and source acceptance

Tests assert the Reports read delegations never fall back to root Prisma and retain selected society across summary/comparison and paginated paths; both SecurityEvent SQL queries execute on the same tenant transaction client. Preexisting selected-society regressions, reporting privacy projections, role gates, filters and error boundaries remain.

The canonical source inventory was regenerated using **the repository's actual TypeScript AST generator** (`node services/api/scripts/tenant-access-inventory.mjs --write`) followed by `node scripts/sync-tenant-access-summary.mjs --write`. Protected CI validated the generated digest and summary, reporting 399 `withTenantContext` calls versus 393 before this slice. A temporary feature-branch regeneration workflow was removed before the protected acceptance run and is absent from the merged tree. No inventory checks were bypassed.
