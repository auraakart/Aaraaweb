# V5.4.19 — Partner owner domain console

The platform partner portal now links to `/partners/domains`. Only server-discovered
OWNER workspaces enumerate claims or expose mutation controls. Every operation
retains the existing owner-only API authorization; branding, commercial-admin or
society-admin roles do not establish domain authority.

The console reuses registration, test DNS verification, challenge replacement
and revocation endpoints. Registration/replacement show one-time TXT proof only
in component memory. Refresh, logout, focus revalidation and workspace switching
clear that proof. The list adds only `verifiedUntil` to its already bounded safe
projection; no proof hash, challenge, user or society operations data is exposed.
Expired verified records display DNS proof expired, and verification never
claims production routing activation.

Replacement/revocation require a three-character-to-500-character reason and
confirmation, then send the listed expectedVersion. Idempotency keys remain
stable for retries of the exact same session/workspace/action/input. A changed
version, identity or payload selects a different operation key. A replay without
the plaintext proof tells the operator to replace it, rather than inventing or
recovering a secret. Server cooldown, rotation/capacity limits and audit history
remain authoritative.

Generation checks, abort signals and current session identity discard late reads
and mutations. A confirmation started before logout cannot submit afterwards.
Permission/read errors remove operator controls and data. The write lock starts
before confirmation to prevent double submission. Partner workspace selection
is disabled during writes.
