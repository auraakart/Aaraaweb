# V5.4.11 — Versioned Partner Domain Registry (development only)

**Boundary:** This persists domain registration, DNS TXT challenge/verification, revocation, and immutable revision events. It does **not** activate web routing, session cookies, society access, paid licenses, app distribution or TLS. Earlier V5.4.2 hostname canonicalization remains authoritative via the existing Node 22-compatible config loader.

- Enabled only when `NODE_ENV=test|development`, `AARAGATE_ENABLE_TEST_DOMAIN_REGISTRY=true` and `AARAGATE_PLATFORM_HOSTNAMES` contains a nonempty bounded JSON array of exact platform-owned DNS hostnames. Otherwise every domain endpoint is not found.
- Owner role is revalidated from active PartnerMembership/User/Partner inside a serialized transaction. Other partner roles (including commercial admins) do not create DNS authority.
- Creates one 256-bit token returned once, stores only SHA-256, requires an exact TXT record on `_aaraagate-verify.{hostname}` within 48 hours, and reads DNS through the server resolver. Caller-submitted proof is never accepted.
- Hostname registry is globally unique even when revoked/expired. The idempotency key is scoped to partner, and changed replays conflict.
- DNS fetch is done *outside* database locks, followed by revalidation and row lock before the state transition. Verified ownership lasts 30 days, with no automatic host activation or assumption of current control afterward.
- Immutable DB event trigger prevents rewriting ownership proof history.
- Rollback: remove runtime endpoints but retain audit tables/history. Destructive schema rollback excluded.
- Acceptance: Prisma validate/generate, tenant inventory reconciliation, typecheck, lint, negative unit cases, fresh Postgres migration and protected CI; real DNS/provider validation explicitly excluded from this slice.

Still required for full V5.4 closure: partner app-audience onboarding/login, verified-domain-to-brand binding with distinct platform approval, multi-host SSR/cookie/session tests, and Android distribution approval policy.
