# V5.4.16 — Server-persisted commercial partner audience

V5.4.14 separated partner/Admin browser storage, but its server-issued token was indistinguishable from an independent-home token. This non-production slice adds an authoritative persisted Session.audience column, default STANDARD for legacy rows, and an SQL CHECK restricting PARTNER to a society-less session.

Dedicated OTP writes PARTNER with empty AppRoles. SessionService rechecks active commercial membership or an unexpired pending invitation on bearer access and refresh. BearerGuard now rejects PARTNER sessions on *all general/resident/guard/finance* routes. The three commercial partner controllers use PartnerBearerGuard, which accepts dedicated tokens and preserves compatible standard Admin tokens. Each service still independently scopes the partner and membership. Existing standard society and independent-home sessions remain unchanged.

Acceptance: Prisma clean/historical upgrade and DB CHECK, partner OTP issuance, ordinary API rejection, permitted partner API, revoked membership, pending invitation, invalid audience and forged society association. No TLS, trusted proxy, host-bound session or actual SSR routing is enabled.

Legacy partner sessions minted before this change are tagged STANDARD by necessity because their original audience was not recorded. Do not enable custom-host routing until those sessions expire or have been revoked and users sign in again. Future slices must implement authenticated server-origin binding, host-only cookies, navigation-versus-mutation Origin policy and cross-host SSR tests. No staging/main promotion or production claim.
