# V5.5.38 — Read-only pinned OCI TEST registry manifest preflight

Baseline: `develop` `f99c114905fabf684f1797d2f23b473b725c6d49`, after V5.5.37 PR #1341 evidence reconciliation. V5.5.37 passed protected offline OCI integrity tests. **V5.5 remains IN_PROGRESS.**

## Implementation

`packages/config/src/android-test-oci-registry.mjs` reuses V5.5.36 signed Ed25519 DSSE and V5.5.37 on-disk OCI manifest/config/layer bytes verification before a read-only OCI registry GET. Fixed operator-controlled digest-addressed `/v2/<repository>/manifests/sha256:<digest>` endpoint requires TLS 1.3, CA trust, certificate hostname verification and pinned server SPKI. Validates OCI manifest media type, exact Docker-Content-Digest, SHA-256 body, and bounded size. Refuses redirects, HTTP, URL credentials, queries, tags, untrusted TLS and response tampering. Operator policy must never come from a partner or caller request.

`scripts/android-test-oci-registry.test.mjs` uses disposable OCI layout, ephemeral signed TEST claim and local TLS CA/server keys. The Repository structure auto-discovers `scripts/check-v4.79.1.10-v5-oci-registry.mjs` without CI YAML edits or Android builds.

## Trust boundary

This checks **only** a TLS-pinned HTTPS registry response against a signed image claim and local disk image bytes. Its ephemeral fixtures do not prove external registry ownership, remote layer bytes, independent production key custody, actual running worker image, authenticated remote worker, immutable mounts or single-use challenge consumption. All authority flags remain false: `externalRegistryAttested`, `registryDigestVerified`, `remoteLayersVerified`, `runtimeImageAttested`, `imageRunningOnAuthenticatedWorker`, `runtimeTransportAuthenticated`, `immutableMountVerified`, `singleUseChallengeConsumed`, `buildExecutionAuthorized`, `artifactProduced`, `dispatchAllowed`.
