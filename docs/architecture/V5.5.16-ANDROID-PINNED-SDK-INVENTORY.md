# V5.5.16 — Exhaustive local TEST SDK and Flutter native-template pins

Baseline: V5.5.15 single-use signed TEST runner evidence accepted through PR #1306, merged as `1f28184466f02d6debc462f403ae8b64aef4d685`, with CI run 38587090379 green.

This slice checks **every regular file and directory** (not just the `--version` executable) in four separately pinned isolated worker roots: complete Flutter SDK, Android SDK, Java home and reviewed Flutter-generated native wrapper template. The caller must provide an independently authenticated immutable runner policy with a canonical isolated workspace, disjoint absolute roots and expected full-tree digest, exact file/directory count and total byte count for each root. Each recursive file is SHA-256 streamed with a size bound and stable path/mode metadata. The entire tree is hashed in deterministic order with an Aaraagate-specific versioned domain prefix. Symlinks, special files, hardlinks, world/group-writable files or directories, unpinned extra files, missing files, path aliases, overlapping roots and changing file metadata are rejected. Both Resident and Guard fixtures plus negative drift/path cases are included in mandatory Node structure tests. Existing V5.5.10 checkout, V5.5.12 executable checks and V5.5.15 server replay-barrier acceptance are required inputs.

**Limitations:** This is a *local byte comparison*, not evidence of a genuine OCI image running or of an authenticated TLS channel. Expected pin sources must be controlled independently of partner/request/worker-provided inputs. The module intentionally **does not** trust a pinned image identifier as runtime attestation. Real SDKs may have symlinks/hardlinks and must be normalized into an immutable, audited, canonical image before this policy can pass. The exhaustive scan should be performed only in a disposable isolated worker against read-only mounts; races outside such mounts are not eliminated by the scan. The receipt explicitly marks `runnerTransportAuthenticated:false`, `runtimeImageAttested:false`, `immutableMountVerified:false`, `artifactProduced:false` and `dispatchAllowed:false`.

No new endpoint, secrets, external provider, productionization, staging/main commits or existing demo APK workflow changes.
