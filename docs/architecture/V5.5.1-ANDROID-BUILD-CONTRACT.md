Baseline: develop `165f645a92724684578c898c15b110c2d1b066d9` after V5.4.20/V5.1.2 protected acceptance. This slice begins V5.5; it does not complete Android build automation or produce APK/AAB artifacts.

## Existing implementation reused

The default Resident demo workflow already generates its Flutter Android wrapper with project name `aaraagate_resident`, organization `com.aaraaplatforms`, Flutter 3.47.0 and Java 17. It publishes only from main. Neither that workflow nor the existing app version/default signing/identity is changed here. A generated namespace inferred from the workflow is not proof of an installed artifact's identity; actual default artifact inspection remains required before packaging changes.

The existing V5.4.20 approved-input ledger fixes the initial applicationId/namespace, app role, label, source SHA, config digest, API origin and test signing reference. New pure functions live in the shared config package; they never fetch a token, execute a shell, create a role, read a database, sign a binary or dispatch a build.

## Build-manifest contract

`planTestAndroidBuild` strictly validates one bounded TEST manifest. It fixes distribution/approval/partner/society IDs, published brand revision, exact source SHA and dependency-lock digest, immutable native identity, role, printable label, canonical allowlisted HTTPS API origin, configuration and icon/splash digests, push-disabled public test Firebase mapping, verified app-link hosts and test signer fingerprint. Unknown keys, paths/script fragments, live signing, default/reserved packages, Java keywords, bidi/control labels, mutable refs and foreign/stale context fail closed. Approval start is inclusive; expiry is exclusive. Asset and signer mappings must be unique and same-owner; duplicate identities/approval rows fail closed.

The caller-supplied context is a **simulation snapshot**, not server authentication. It must eventually be assembled from independently reauthorized persisted approval/ownership/licensing, source/lock, published branding, sanitized assets and configured identity mappings. The function cannot establish that those snapshots are genuine, current or authoritative. Its output explicitly says `dispatchAllowed:false`, `testOnly:true` and `requiresVersionReservation:true`; never use it as a commercial entitlement or session principal.

A deep-frozen copy keeps caller state unchanged. Role resolves to the existing `apps/resident` or `apps/guard`; artifact naming uses validated UUID/role fields only. Native asset byte checking recomputes exact SHA-256 under a 2 MiB cap. It does not decode or sanitize an image; a trusted asset pipeline must perform those operations before marking metadata stripped and approved. Initial test Firebase mappings require push disabled; no real Firebase app or external provider is provisioned.

## Provenance contract

`recordTestAndroidProvenance` refuses unreserved/invalid version codes, source/lock/manifest or signer drift, demo fixtures, unverified archives, unknown/secret-bearing evidence and missing/duplicate APK/AAB checksums. Evidence references Flutter 3.47.0, Java 17, Node 22 and pnpm 10.15.0. It records only immutable TEST, unpublished provenance. A supplied `archiveVerified` flag is not proof of archive/signature verification: the future trusted builder must compute it from the actual outputs. No synthetic fixture is advertised as a built artifact.
