# V5.5.20 — TEST native overlay integrity and Android version policy

After V5.5.19 merged to develop at `d5e36640fe996f241e3198fbecbeeafe803f5976`, this slice verifies the last non-executable native overlay produced by V5.5.17. It re-enumerates every path in a disposable TEST directory, rejects symlink/hardlink/special and group/world-writable entries, checks all twelve input SHA-256 hashes and the thirteenth receipt, verifies manifest/reservation/source/lock/role, PNG approval digests, Kotlin package, launcher theme and Android 12 light/night splash resources. A canonical final digest binds the verified staged inputs. The patch planner enforces `minSdk = 24`, `targetSdk = 36`, `compileSdk = 36`, compatible with the planned Flutter 3.47 Android baseline. Both Resident and Guard identities have regression cases, including tampering and rogue extra files.

This is only a **final native input overlay verification**. A genuine Flutter Android wrapper must still be created by an independently trusted, isolated runner using a pinned SDK; the wrapper must be compared against the reviewed template, receive these overlay resources, and undergo another whole-wrapper verification before any compile/packaging. This module never executes Flutter, Java, Gradle or APK signing, and never claims `flutterWrapperGenerated`, `runnerImageAttested`, `dispatchAllowed`, `artifactProduced` or `archiveVerified`. Further requirements: provision independently attested runner, secure single-use authorization transitions, perform TEST builds, verify package, ABI, signing certificate and SHA-256, and test Resident/Guard installation isolation. No release-branch changes.
