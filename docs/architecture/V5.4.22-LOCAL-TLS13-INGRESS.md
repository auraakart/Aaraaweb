# V5.4.22 — Local TLS 1.3 ingress isolation acceptance

Baseline: `develop` `248e038b99e2cbe22678d227b5aaef141098e2c2`, after V5.4.21 protected acceptance.

This slice adds a **real loopback HTTPS integration test** using a temporary OpenSSL-generated, self-signed SAN certificate for the platform host and two example partner hosts. The Node.js test client explicitly verifies the disposable CA and connects with TLS 1.3; a fixed test proxy forwards to one hardcoded loopback HTTP double.

Covered: TLS 1.2 refusal; untrusted CA and wrong SAN rejection; exact SNI-to-Host equivalence; canonical allowlisted Host selection; rejection of spoofed Forwarded and X-Forwarded headers; same-host Origin on mutations; cross-site rejection; strict method rejection; no-store/private and Host/Origin/Cookie Vary; foreign-partner redirect denial; and prevention of unauthorized requests from reaching the fixed backend. The header-only fixture deliberately rejects non-empty POST bodies and does not exercise real cookie authorization.

The test is automatically discovered by the existing `scripts/check-v4.79*.mjs` Repository structure job. No CI YAML, Next routing or API auth changes and no Android rebuild are necessary.

**Limitations:** self-signed local transport only, not deployed trusted reverse proxy, production certificate, remote image attestation, full Next/API HTTPS browser session, real Partner A/B Android distribution, or evidence of production readiness. V5.4, V5.5 and V5.6 remain open; `staging` and `main` must not be changed.
