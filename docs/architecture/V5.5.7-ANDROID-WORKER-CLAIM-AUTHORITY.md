# V5.5.7 — TEST Android worker claim authority (not execution)

Baseline: V5.5.6 [PR #1297](https://github.com/auraakart/Aaraaweb/pull/1297), [CI #38557532566](https://github.com/auraakart/Aaraaweb/actions/runs/38557532566), merged into develop at `616beb7682c1e19420015134b19a53a74c59b01a`.

A **single immutable claim per Android version reservation** is now represented by `PartnerAndroidBuildWorkerClaim`. This is an internal service only, not a public worker route, build queue, executable capability or signed APK.

The authenticated society principal is supplied by a trusted server caller; it must NEVER originate from worker input. The worker provides a domain-separated HMAC-SHA256 assertion using a separately provisioned 256-bit hexadecimal `AARAGATE_TEST_ANDROID_WORKER_HMAC_KEY`. Missing key disables claiming. The canonical signed tuple binds society, distribution, immutable reservation and revision digest, requesting actor, grant/allocation versions, versionCode, TEST worker ID, nonce and timestamps. The server checks a 30-second freshness window, ≤120-second expiry, and constant-time signature comparison. Only SHA256 hashes of nonce and signature are retained; never the secret or raw assertion.

A live `BEFORE_DISPATCH` licensing checkpoint is required. A second live allocation/distribution/latest-reviewed TEST revision and exact reservation check occurs before insert, with a database trigger repeating current approved allocation/revision and timestamp guards. Unique reservation ID plus immutable record trigger prevent any second claim including an identical signed replay. Result explicitly states `CLAIMED_TEST_NO_EXECUTION`, `dispatchAllowed:false`, `executionStarted:false` and `artifactProduced:false`.

The separate authenticated worker transport, a distinct single-use **execution consumption** guard, actual Flutter/Gradle process, pinned toolchain/source/asset verification, fresh `BEFORE_COMPLETION` checkpoint, signer/archive checks and provenance **are not yet implemented**. A claim MUST NOT be interpreted as an execution or publication permit. No changes to staging/main or demo APK workflow.

Acceptance: tested authenticated claim, default-disabled key, tampering/replay rejection, expired assertions, revoked distribution, missing independent revision review, version/identity drift and unique reservation conflict; protected PostgreSQL migration and all required CI gates must be green before develop merge.
