## Scope and identified gap

V5.6.3 tests the real NotificationRealtimeService with mocked adapters; earlier payment-integrity PostgreSQL tests already cover a tenant in one society, nonresident owner exclusion, expiry/revocation, cross-society invoice access, and payment idempotency. This slice adds one focused **migrated PostgreSQL** test for a globally shared tenant identity legitimately associated with *two different society/unit pairs*, which could belong to separate commercial partners.

The new test runs only when DATABASE_URL is supplied (inside the existing dedicated disposable-PostgreSQL suite), creates one additional occupancy in the already randomized second test society, and deletes that temporary occupancy in `finally`. It checks:

- Both valid society/unit pairs return their tenant recipient without duplicating or widening scopes.
- The two crossed society/unit pairs return **no** recipient.
- `effectiveTo` is strictly exclusive at the exact cutoff timestamp; expiry of one property never revokes the other.
- Disabling the second occupancy's `gateNotificationEnabled` blocks its notification while the first stays deliverable.

No application behavior, migration, schema, API contract, auth bypass, workflow YAML or external integration is changed. This test contributes specifically to V5.6.2 `V56-TENANT-02` **CI/TEST_DB** evidence; it does not execute that whole acceptance case because independent end-to-end user/device authorization evidence is still missing.
