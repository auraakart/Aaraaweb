# V5.4.13 — Domain revocation and challenge reissue

**Non-production scope.** Follow V5.4.12 domain verification without activating any host routing or cross-partner access.

Authenticated current partner OWNER can POST `/partners/:partnerId/domains/:claimId/revoke` or `/reissue` with `expectedVersion`, UUID `idempotencyKey` and reason. Both actions recheck active owner/partner under a partner-row lock, then lock the scoped claim.

Revocation changes state to REVOKED, clears verification timestamps and appends immutable event. Reissue rotates a 256-bit one-time challenge and stored SHA-256 digest, resets attempts, clears verification timestamps and returns the plaintext challenge only on the first request. Replays return null challenge, and conflicting/superseded replays fail closed. All records have optimistic version and immutable event/unique idempotency key. Reissue requires a sixty-second challenge age and at most ten lifetime rotations per claim. Existing domains do not automatically re-route.

V5.4.12 verification now uses challengeIssuedAt rather than the original registration date for seven-day proof validity. Legacy registrations are backfilled with original createdAt. No live DNS/TLS/cookie/session authorization or production distribution.
