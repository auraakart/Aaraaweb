# V5.5.18 — Real TEST runner identity-only mTLS client and signed nonce proof

Baseline: V5.5.17 PR #1308 merged into develop at `f37a1c438fde31348c5a62c48d384f9c646e99a3` following CI run 38591175792.

This slice implements a real Node.js `https.request` mutual-TLS 1.3 client to a fixed `POST /v1/test-runner/identity` endpoint using **server-owned, separately provisioned** CA trust, TLS client certificate and private key, server certificate SPKI SHA-256 pin and an independently pinned Ed25519 worker response key. Only canonical `https://` endpoints matching protected config are supported; URL credentials, redirects, query strings, protocol downgrades, altered or incorrect cert SPKI, unknown keys, unsigned replies, oversized responses and stale/mismatched nonces are rejected. A cryptographically fresh 32-byte nonce is bound to an already persisted V5.5.15 signed acceptance (acceptance, challenge and consumption IDs; worker/run, manifest/source/lock/role and claimed immutable image digest); the worker must sign a timestamped echo with a dedicated cryptographic domain. A bounded request, response body and timeout prevent excessive I/O. The resulting receipt reports an authenticated pinned TLS peer and signed application-layer response.

**This does not provision any remote worker.** Tests launch an ephemeral local HTTPS server requiring a verified client certificate, create disposable CA/client/server certificates at test runtime with OpenSSL, and test both app roles and multiple fail-closed attack cases. No cryptographic credentials or private keys are committed. For real deployment the server **must** enforce client certificate validation and credential rotation, and its signing key must remain isolated; the client cannot independently prove the remote server's mTLS enforcement policy. The signed `imageDigest` is only a **claim**, not proof that the expected OCI image ran. The receipt explicitly marks `runtimeImageAttested:false`, `serverMutualTlsPolicyAttested:false`, `immutableMountVerified:false`, `buildExecutionAuthorized:false`, `dispatchAllowed:false` and `artifactProduced:false`.

This identity-only endpoint **does not** upload sources, run any commands, build APK/AAB, create signing artifacts, expose a new public API route or alter the existing demo pipeline. Client credentials and expected SPKI/worker key must be loaded from protected server/runner secret configuration, never partner or HTTP request payloads. Remote worker provisioning, independently verified image runtime/mounts, atomic execution authorization and end-to-end APK/AAB signing/validation remain separate required slices.

Run `node --test scripts/android-build-contract.test.mjs` and full required protected CI before merging to develop. Staging and main must remain untouched.
