# V5.5.47 — Bind operator TEST evidence to secure file identity and content

## Root cause

The V5.5.46 operator-only TEST mTLS evidence probe correctly required explicit TEST approval and off-repository credentials, but its input files were **validated by path and permissions and then reopened later**. A malicious or accidental file replacement between those steps could substitute a certificate, policy or trust pin after the initial checks. The operator plan JSON itself also lacked a canonical, non-symlinked, private-permissions reader. This is a narrow local file-integrity race, **not** evidence of an actual independent TEST worker or a production vulnerability.

## Bounded fix

- Reuse the existing V5.5.46 read-only TEST probe; no new network, build, signing or approval pathway.
- Open each input with `O_NOFOLLOW | O_NONBLOCK | O_RDONLY`; reject symlinks, alternate inodes, nonregular objects and oversized files. Confirm file descriptor identity and stat stability before and after reading.
- Record a private in-memory SHA-256 and stat fingerprint for every of the seven operator-provided JSON/PEM inputs during plan validation. At load time, require byte digest, inode, size, mode and modification/change timestamps to match. Disallow hard-linked reuse of one trust file in multiple roles.
- Associate the validated files with an unforgeable module-local `WeakMap` snapshot keyed by the exact frozen validated record. Reject forged/cloned records and authorization revocation between validation and loading.
- Apply the same bounded no-follow, private-mode reader to the operator plan itself, which must reside outside the checkout. Never log path, content, credential, key or raw signed claim on failures.
- Extend the existing `scripts/v5.5.46-readonly-runtime-probe.test.mjs` with race, replacement, permission-change, plan-symlink and hardlink negative tests. Reuse the `scripts/check-v4.79.1.46-v5-test-runtime-operator-probe.mjs` auto-discovered CI test path; do not add or duplicate whole CI matrices.
- Reconcile the already verified V5.5.46 protected PR #1403 / CI #38937824571 / merge `a73c7f688677146ce2318a0a17585795a5533100` into the checked-in V5 manifest; V5.5 remains `IN_PROGRESS`.

## Operator requirements

Supply operator plan and **all seven** evidence/credential files as non-symlinked, unique, canonical absolute paths in a trusted private directory outside the Git checkout. The plan and client private key must be `0600` or more restrictive; an ordinary directory with owner-only `0700` access is recommended. Files must not be replaced, rewritten, re-signed, chmod'd or hard-linked between validation and read. If any change is required, restart the operator process with independently reviewed source/image/endpoint pins. The probe remains opt-in and read-only, with no automatic remote worker dispatch.

This closes only the local **file input substitution** risk. It **does not** prove that a remote OCI image/namespace/process exists or is independently attested. The repository cannot provision independent operator-controlled TEST registry/observer, hold signing keys outside the platform, accept physical device results or consume persistent cross-run challenges without external actors. Issue [#1380](https://github.com/auraakart/Aaraaweb/issues/1380) must remain OPEN until genuine external evidence exists, and all 15 V5.6 formal TEST acceptance cases remain `NOT_EXECUTED`. V5.6 remains `PLANNED`.

## Branch and quality

Feature branch to `develop` only, all existing protected CI gates before merge. No runtime API SQL/Prisma, generated tenant-access inventory, Android build, partner signing, productionization, release/staging/main commit or release authority changes.
