# V5.4.24 — Operator-gated nonproduction HTTPS ingress probe

Baseline: `develop` at `414dbcf8d6a8a73e809f972a3393030af424b497`. V5.4.23's actual Next.js partner-host SSR, encrypted cookies, refresh/logout and cross-host rejection behind a **local** TLS 1.3 proxy passed protected CI. External ingress readiness remains unverified.

## Delivered

`scripts/v5.4.24-ingress-acceptance.mjs` implements a read-only external HTTPS transport checker, and `scripts/v5.4.24-run-ingress-probe.mjs` is a **manual opt-in** CLI. The acceptance plan must have exactly these fields:

```json
{
  "schemaVersion": 1,
  "testOnly": true,
  "environment": "ISOLATED_NONPRODUCTION",
  "hostname": "portal.qa.partner.in",
  "approvedHost": "portal.qa.partner.in",
  "approvedSpkiSha256": "<64 lowercase hexadecimal characters>",
  "probeOnly": true
}
```

The sample hostname and placeholder pin are illustrative, not a reachable/approved external endpoint. A reviewer must independently establish the actual nonproduction DNS identity, public TLS chain, SHA-256 of the serving TLS leaf **SPKI** and ingress ownership. The CLI accepts no destination URL, IP literal, port, custom CA, authentication token, body or redirect target. It requires `NODE_ENV=test` or `development`, the exact approved hostname and an explicit manual confirmation before any network call. Only TLS 1.3, normal certificate validation, matching DNS/SNI and the reviewed SPKI pin are allowed.

It makes three **unauthenticated** bounded GET requests to `/partner-host`: normal response, spoofed `X-Forwarded-Host`, and cross-origin `Origin`. It checks expected allowed/denied statuses, no-store, Host Vary, nosniff and safe same-host/relative Location headers. Bodies and Set-Cookie are never printed or retained. Denied statuses alone cannot prove the request never reached a backend: separate ingress and Next/API logs must establish that.

## Explicit operator-only invocation

Write an *untracked local* reviewed JSON plan, then run from a controlled nonproduction workstation:

```bash
NODE_ENV=test \
AARAGATE_V5_APPROVED_TEST_HOST=portal.qa.partner.in \
AARAGATE_V5_INGRESS_PROBE_CONFIRM=I_APPROVE_READ_ONLY_TEST_PROBE \
node scripts/v5.4.24-run-ingress-probe.mjs /path/to/reviewed-test-plan.json
```

**Do not execute** until the actual hostname and pin are reviewed; do not use production ingress, live partner credentials or a partner's real device. The CLI is not invoked in GitHub CI. The existing `check-v4.79*.mjs` CI discovery instead runs only `scripts/v5.4.24-ingress-acceptance.test.mjs`, which tests a loopback self-signed TLS fixture, SPKI-pin mismatch and fail-closed plan rejection without external network activity.

## Evidence and remaining gates

The probe's result intentionally retains `externalOperatorAttested:false`, `remoteDeploymentOwnershipVerified:false`, `actualPartnerSessionAuthenticated:false`, `productionRoutingAuthorized:false`, `distributionAuthorized:false`, and both promotion controls false. A passing TLS probe does **not** authenticate the remote ingress operator or demonstrate actual Next/API session isolation under a remotely controlled ingress. Independent deployment attestation, key custody, source/config pinning, firewall bypass denial, actual browser HTTPS/session acceptance, cross-partner logs, rollback proof and separate review are still required. V5.4 is not complete; V5.5 partner-specific Android acceptance and V5.6 engineering closure are separate. No productionization or staging/main changes.
