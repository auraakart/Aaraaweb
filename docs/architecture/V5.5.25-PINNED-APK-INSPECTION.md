# V5.5.25 — TEST APK inspection using independently pinned Android tools

Baseline: V5.5.24 co-installation guardrail merged into `develop` as `ee2c64df626c7f2ffbe5da92ef2506b637a1873d` (PR #1315), following the green protected CI workflow.

This non-production, **read-only** adapter inspects an existing TEST APK candidate only. It first verifies the bounded ZIP32/CRC entry inventory from V5.5.23, then verifies the exact SHA-256 bytes and executable permissions for independently pinned `aapt2` and `apksigner`. It invokes **fixed argv, no shell**, with bounded stdout and timeout, no update/sign/publish operations. It rechecks both tool binary SHA-256 and APK SHA-256 after each invocation. The `aapt2 dump badging` output must report exact approved package name, reserved versionCode, minSdk 24, targetSdk 36, reviewed ABI list (including arm64-v8a); the `apksigner verify --verbose --print-certs --min-sdk-version 24` output must report exactly one signer with approved TEST SHA-256 certificate digest and v2 scheme verification. Foreign identities, executables, changed files, invalid tool outputs and non-TEST requests fail closed.

**Proof boundary:** This adapter can report that *pinned locally executed inspection tools* passed; it does not attest the machine/container image that executed them or grant server-side artifact acceptance. Its result deliberately retains `independentlyAttestedRunner:false`, `actualSignerVerifiedByTrustedAttestedRunner:false`, `testArtifactAuthorized:false`, `artifactPublished:false`, `buildExecutionAuthorized:false`, and `dispatchAllowed:false`. Integration tests use synthetic ZIP bytes and disposable fake executables, not genuine signed Android packages or genuine Android SDK tooling. The AAB bundletool path, deployed runner, immutable checkout, live license completion check and real APK/ABI/on-device validation remain pending.

Only `develop` changes after mandatory CI; no productionization, cloud provisioning, signing credentials, staging or main updates.
