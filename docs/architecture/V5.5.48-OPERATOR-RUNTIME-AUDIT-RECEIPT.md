# V5.5.48 — Auditable, explicitly non-authoritative TEST runner claim receipt

**Baseline:** `develop` `76996a136a519bff9a178f85655bf45269649a23` after PR #1404 passed protected CI #38941746329 and merged as V5.5.47. The V5.5.47 operator-file integrity work is reconciled into the current manifest in this PR.

## Purpose

V5.5.46 provides an explicitly approved operator-invoked read-only TLS 1.3/mTLS probe and V5.5.47 ensures its off-repository trust files cannot be replaced between validation and use. But the command's previous stdout summary omitted the unique challenge/acceptance IDs, TLS server key fingerprint, verification timestamp, and digests of the received signed claim. Without those correlators an independent TEST operator cannot conveniently associate a **specific local observation** with a separately measured OCI worker/process/mount record. This is an operator **traceability** improvement, not independent OCI measurement.

## Change

The existing operator probe now uses `scripts/v5.5.48-readonly-runtime-audit-receipt.mjs` to convert an **already validated** read-only probe result into a small, bounded JSON audit receipt. Exact operator-pinned source Git SHA, OCI image digest, and server SPKI SHA-256 must match. Strict input validation requires the session's TLS 1.3 peer, client certificate, fresh nonce, and independent runtime-claim signatures to have verified. The receipt carries **only** source/image/worker/run identifiers, challenge and acceptance IDs, verified time, server SPKI, and SHA-256 digests of the request nonce, signed runtime envelope, and transport observer signature. Raw nonce, raw signed envelope and PEM key data are deliberately excluded.

A deterministic `receiptSha256` fingerprints the JSON object for accidental changes during manual handoff. **This hash is not a signature or an authentication mechanism**: a malicious holder could recompute it, so independent operator transport/custody and separate external image/process measurement are still mandatory. The offline verifier rejects tampered fields, foreign operator pins, unknown properties, fabricated external authority, and malformed receipts but **does not** approve Partner A/B binaries, TEST build execution, distribution, or V5.6 release.

New no-network negative tests run through the existing `scripts/check-v4.79*.mjs` repository CI gate. All standard protected checks must pass before `develop` merge. The repo's TEST simulation cannot be used as external attestation.

## Operator use

Use the existing **operator-controlled** opt-in command and secret plan from `docs/architecture/V5.5.46-TEST-RUNNER-OPERATOR-READONLY-PROBE.md`. Capture stdout as a private TEST claim-observation receipt, alongside independent observer measurements with their own evidence chain, and compare the candidate source/image, TLS peer, challenge and signed evidence digests.

For manual integrity inspection, an operator can load the JSON and use:

```js
import {verifyReadOnlyTestRuntimeAuditReceipt}
  from './scripts/v5.5.48-readonly-runtime-audit-receipt.mjs';
verifyReadOnlyTestRuntimeAuditReceipt(receipt, {
  sourceSha: reviewedGitSha,
  imageDigest: independentlyReviewedOciDigest,
  serverSpkiSha256: independentlyReviewedTlsServerSpkiSha256
});
```

**Passing local receipt integrity is not proof of remote runtime attestation.** Issue [#1380](https://github.com/auraakart/Aaraaweb/issues/1380) remains open: separately provisioned TEST OCI registry/runner/observer, genuine out-of-worker image/process/mount measurements, persisted replay challenge consumption, explicit bounded TEST-only builder approval, independent partner signer/APK/AAB and device co-install/rollback evidence. V5.5 remains `IN_PROGRESS`; V5.6 remains `PLANNED`, with 15 formal TEST cases `NOT_EXECUTED`.

No productionization, staging/main promotion, release authorization, Android build job or dependency changes.
