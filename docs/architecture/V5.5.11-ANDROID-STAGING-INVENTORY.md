# V5.5.11 — Verify staged TEST Android bytes at consumption boundary

After V5.5.10 validates exact clean source and dependency lock, re-read the **actual bytes** staged by V5.5.9. The `verifyStagedTestAndroidInventory` helper accepts a TEST non-dispatchable plan, immutable reservation and the disposable staging receipt. It requires an OS-temporary canonical staging directory, an exact eight-file inventory (four native patches, two PNGs, and two receipts), no symlinks/special files, correct distribution/source/lock/application/version identity, unchanged JSON receipts and byte-for-byte matching SHA-256 and size for every reviewed native patch and both approved PNG files. It rejects unexpected files, changed Gradle/manifest/Kotlin content, modified artwork, foreign reservations and dispatchable metadata.

The helper does not grant runner authority. An attacker controlling both the inventory and the workspace could recompute hashes; expected provenance and pins still require an **independently authenticated worker** and an authoritative live server checkpoint. Verification is also subject to filesystem races until a future builder enforces workspace isolation and consumption ordering. No Flutter wrapper, Gradle/Flutter execution, real signing, APK/AAB, upload, migration or staging/main modification is included.

Tests: `node --test scripts/android-build-contract.test.mjs` includes Resident/Guard success and malicious file mutation/inventory cases. Full protected CI is the merge gate.
