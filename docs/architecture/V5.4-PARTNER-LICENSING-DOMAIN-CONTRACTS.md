## V5.4.1 — Commercial licensing contract before activation

`services/api/src/entitlements/partner-license-contract.ts` provides deterministic, pure functions only:

- `licensePhaseAt`: checks strict UTC input and valid calendar dates. A period begins inclusively and expires at an **exclusive** end instant; optional grace is explicit and exclusive. No grace duration, pricing, auto-renewal or legal meaning is invented.
- `intersectPartnerLicenseFeatures`: calculates the *candidate* intersection of platform safety, partner licence, society subscription and society operational feature allowlists, using the **existing** ProductFeature catalogue. Reject duplicate/unknown values; stable output follows existing enum order. This **never grants** user permissions, replaces FeatureGuard or modifies society data.
- `previewPartnerCapacity`: rejects bad integer inputs and previews whether adding a society fits a stated maximum. It does not reserve capacity, determine partner ownership or prevent concurrent oversubscription. Future implementation must use a scoped transaction, version preconditions and idempotency.

**Non-negotiable cutover gate:** Existing `EntitlementService.current` and Society.productTier/featureOverrides continue as live authority for all legacy societies. The V5.1.0 historical compatibility snapshot remains evidence, not a live grant. No live license resolver or partner portal access until ownership history/transfer rules, audience policy, simulated plan grants, compatibility equality, transactional allocation, and essential gate/SOS grace behavior are reviewed and tested.

Required focused tests: allowlist intersection and unknown-field rejection, legacy tier unchanged, start/end/grace timestamp boundaries, impossible dates, zero/negative/oversubscribed capacity, full existing API tests. The canonical full protected PR gates remain mandatory; no staging/main promotion.

## V5.4.2 — Verified-only hostname candidate contract

Implemented in the existing shared config package (`packages/config/src/partner-domain-contract.mjs`) instead of a new server or partner-specific web fork. A one-line canonical preflight gate runs `scripts/partner-domain-contract.test.mjs` with Node's built-in test runner. The pure contract:

- canonicalizes lowercase/IDNA ASCII DNS hostnames; rejects URL syntax, credentials, paths, query/fragment, explicit ports, wildcard, invalid labels, numeric IPs, and localhost/internal/test/example hosts;
- accepts a caller-owned explicit canonical-host reserve list (no hard-coded assumption about real production domains), including subdomains; refuses unreviewed ownership collisions regardless of pending, expired or revoked status;
- resolves **one exact** verified registry row within a checked UTC verification validity interval, with duplicate/unknown/unverified/expired/invalid rows returning no presentation candidate;
- does not read request headers, forwarding headers, DNS, certificates, cookies, HTTP responses or tenant data. A future HTTP adapter MUST use raw Host and only honor forwarded host when validated against a **configured trusted proxy**. Unknown/custom or forged hosts must fail closed before application/login rendering.

Resolution returns an immutable `{hostname,partnerId,brandId}` *candidate only*, never a permission, entitlement, session or verified proof of DNS control. Future partner-domain records must be unique and versioned; a real DNS TXT verifier with challenge expiry, ownership proof, HTTPS and trusted proxy rules is required **before** any host is activated. No live DNS/provider/production integration, partner portal, payment, SSL issuance or main/staging promotion is performed in this slice.

The registry, trusted HTTP adapter and live license enforcement remain separately gated in V5.4.3–V5.4.7. Existing Aaraagate identities and society-scoped operations are unchanged.
