# V5.5.49 — Stop duplicate full app regression for isolated TEST operator tools

## Verified cause of repeated delay

The live `develop` baseline is `d6c15400e195030bd1d10d6cec65a9a074e449b4` (V5.5.48, PR #1405, full CI #38943169576 green). GitHub workflow `.github/workflows/ci.yml` already has a path-sensitive change-scope gate, but it conservatively marks **every** `scripts/` file except `scripts/check-v*.mjs` as a change requiring full API, Admin, Resident and Guard Flutter regression. Consequently isolated V5.5.46–48 TEST operator CLI policy/test/receipt code and documentation unnecessarily incurred unrelated broad app suites on each PR, despite the affected code already being tested by the required Repository structure job. This is **CI selection overhead**, not a failed product test.

An **independent** issue #1380 still blocks actual V5.5/V5.6 external acceptance: no separately administered OCI TEST worker/observer, independently held signer custody, real Partner A/B signed APK/AAB, or physical-device acceptance. Fixing CI scope does not resolve this external dependency, and the 15 formal TEST cases remain NOT_EXECUTED.

## Narrow change

`scripts/classify-v5-test-operator-change.mjs` classifies a PR's exact base/head Git diff only when **at least one** path matches an explicit reviewed allowlist:

- V5.5.46 existing read-only TEST operator probe policy, CLI and associated regression tests
- V5.5.48 existing bounded read-only local claim receipt verifier and regression tests
- Accompanying ordinary `docs/**/*.md` or `docs/**/*.json`

The classifier denies empty change sets, duplicate or malformed paths, unknown paths, deletes, renames, symlink/path aliases in names, any `services/api/`, `packages/`, `apps/`, `.github/`, dependency/lockfile changes, and changes to the `scripts/check-v4.79.1.46*` / `scripts/check-v4.79.1.48*` test runner hooks. A PR involving one or more such paths uses the **existing broad CI scope**, not the fast path.

For only allowlisted operator files the protected `change-scope` job runs the tracked-secret scanner, keeps **Repository structure**, existing mandatory operator regression suites, **Mastermind preflight**, dependency-security wrapper and **Required merge gates**, but can skip unrelated full application API/Admin/Flutter validation. The workflow itself, classifier and its new tests are **not** allowlisted: this initial PR must pass the original full suites.

`scripts/classify-v5-test-operator-change.test.mjs` tests the closed allowlist, mixed runtime changes, malformed input, deletion/rename, known cross-client and SQL changes, and invalid Git revisions. The new `scripts/check-v4.79.1.49-v5-test-operator-scope.mjs` runs those no-network tests on every PR under the existing Repository structure gate and additionally checks that no merge/security gating was removed.

No widening to arbitrary `scripts/v5*` paths. No changes to TEST runner/build workflows, gate authorization, app code, database, tenant-access inventory, APK signing, or productionization. `develop` PR auto-merge only after required protected CI. `staging` and `main` remain unchanged.
