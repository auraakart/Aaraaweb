# V5.5.27 — Pinned read-only TEST AAB manifest validation

Baseline: V5.5.26 PR #1317 merged to `develop` at `3cfb3ff22ef84da73d247239b65f6f4b7a93caf8` with all mandatory gates passed.

This implementation complements the V5.5.25 APK-only pinned inspection and V5.5.26 ZIP layout hardening with an AAB-specific inspection adapter. A candidate must first pass the bounded structural ZIP32/CRC and immutable TEST reservation checks. The read-only adapter requires independently supplied exact SHA-256 pins and canonical nonlinked read-only bundletool JAR plus executable Java binary, then runs fixed-argument `java -jar bundletool.jar validate --bundle=<artifact>` followed by separate `dump manifest --xpath` lookups. It validates the approved application package, reserved versionCode, minimum SDK 24 and target SDK 36. Pinned Java/JAR and AAB hashes are rechecked after each command.

No shell, writable output target, arbitrary CLI parameters or user-provided tool paths are accepted by these validation contracts. Actual trusted-runner isolation and the independent origin of tool pins remain **external prerequisites**: the adapter cannot authenticate its own host, prevent networking at the OS layer, attest downloaded binaries or validate certificates. `artifactApproved:false`, `testAabSignerVerified:false`, `buildExecutionAuthorized:false`, `artifactPublished:false` and `dispatchAllowed:false` remain explicit. This does not replace AAB JAR signer verification or APK cryptographic certificate checks.

Targeted regression fixtures use **synthetic ZIP content and a fake Java stub**, not genuine bundletool or a genuine signed Android App Bundle. No APK/AAB generated, signed, installed, dispatched or published. No staging/main promotion or productionization.

Bundletool CLI reference: https://github.com/google/bundletool/blob/master/src/main/java/com/android/tools/build/bundletool/commands/DumpCommand.java
