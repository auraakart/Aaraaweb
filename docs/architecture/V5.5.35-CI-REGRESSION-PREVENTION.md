# V5.5.35 — Prevent recurring selective-CI syntax regressions

Root cause: while extending the scoped Android matrix in V5.5.33/V5.5.34, automated string replacement
introduced malformed Bash quoting and duplicated a large segment of the protected CI workflow.
This blocked GitHub job evaluation or change-scope before reaching Android. The earlier underlying
Build Tools 37 report mismatch had already been fixed in V5.5.32.

PR #1326, protected run 38669336722, passed Resident/Guard real APK and AAB smoke, the
independent cross-role metadata comparison, full API/Admin/Flutter, and required merge gates.
V5.5.34 merged at 95c724ae60b047fb1fd06aaa30db9012606c5b2f.

The new repository invariant guard runs automatically via the existing lightweight
`scripts/check-v4.79*.mjs` auto-discovery mechanism; it does NOT modify ci.yml or
start another Android build. It parses literal YAML run blocks, applies `bash -n` to
each (no command execution), rejects missing/duplicated sensitive CI jobs, validates
the exact anchored quoted Android change-scope matcher against its intended file
allowlist/denylist and verifies the protected Required merge gate cannot ignore a
failed Android smoke result. Negative cases exercise an unbalanced quote and a
duplicate job declaration. Future CI edits should run this guard locally before
committing so even invalid GitHub workflow documents can be caught before PR.

Scope is CI reliability and nonproduction verification only. All trusted runner
attestation, partner-specific Android builds, signing, installation and publishing
remain explicitly unproven. Staging/main are untouched.
