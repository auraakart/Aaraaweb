# V5.5.6 — Kotlin Flutter TEST Android native wrapper patch planning

Baseline: V5.5.5 [PR #1296](https://github.com/auraakart/Aaraaweb/pull/1296), [CI #38550926469](https://github.com/auraakart/Aaraaweb/actions/runs/38550926469), develop merge `1d4758f5409fa0ae9621dc441b56f376e78b0782`.

`planTestAndroidNativeWrapperPatch(plan,reservation,generated)` prepares **pure non-executing** native patch data from an exact V5.5.1 TEST plan, V5.5.3 reserved versionCode, and separately trusted Flutter 3.47 Kotlin wrapper snapshot for an existing Resident/Guard app.

It fails closed unless the template is recognizably the *unmodified* `com.aaraaplatforms.aaraagate_resident` / `..._guard` Flutter project; rejects foreign or duplicated Gradle identity/version, dangerous manifest DTD, debuggable/cleartext flags, existing autoVerify and release signing, and any extra inputs. Native Kotlin Gradle output pins requested TEST `applicationId`, `namespace`, versionCode, compileSdk=36 and minSdk=23. AndroidManifest.xml uses escaped reviewed brand label, TEST icon and HTTPS-only verified app-link filters. The Kotlin activity is relocated under the validated partner package; an explicit obsolete-path marker instructs a future isolated worker to remove the old source. Splash launch-background XML references the verified V5.5.4 PNG overlay. Full styles/Android 12 splash integration remains outstanding.

**No Gradle or Flutter command is run; no file is staged; no worker, credential, live authority, actual installed app, APK/AAB, signer evidence or build provenance is produced.** The response is `dispatchAllowed:false`, `artifactProduced:false` and `requiresTrustedWorker:true` with explicit unresolved checks. A future worker must authenticate separately, validate source and template hashes, call live authority before dispatch and completion, stage output in ephemeral workspace, integrate splash theme, use sanitized PNG bytes, verify TEST signer/archives, and clean up in finally.

Tests cover resident/guard identity, app links, Kotlin relocation, XML escaping and malformed/injected template and stale reservation inputs. Default demo workflow and staging/main are unchanged. No DB migration or API route is introduced.
