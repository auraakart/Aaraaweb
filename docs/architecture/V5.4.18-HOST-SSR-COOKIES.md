# V5.4.18 — Direct-host development SSR and encrypted host-only cookies

The Next Admin application now isolates partner origins into `/partner-host`.
Root navigation redirects to the exact canonical HTTPS raw Host; partner origins
cannot serve society-admin or platform partner pages. The initial absolute
rewrite used Next's internal localhost URL and re-entered middleware with a
different Host, causing the observed 404. A canonical same-host redirect removes
that internal proxy hop. Fixed-origin Node HTTP(S) transport preserves raw Host
when contacting the API; the incoming hostname never chooses the upstream URL.

This path requires NODE_ENV=test/development and
AARAGATE_ENABLE_TEST_HOST_WEB=true, an explicit AARAGATE_PLATFORM_HOSTNAMES JSON
array, AARAGATE_HOST_WEB_API_BASE_URL (fixed origin, HTTPS or loopback HTTP), and
AARAGATE_HOST_WEB_COOKIE_KEY (server-only 32 random bytes encoded as 64 lowercase
hex characters). The API also requires the existing test-host-session flag and
matching platform hostname configuration. Do not expose the cookie key through
NEXT_PUBLIC variables, commit it, or log it. Production remains disabled even
when the web flag is set.

Only canonical ASCII raw Host participates in routing. Forwarded is rejected.
Next synthesizes X-Forwarded-Host on direct requests; it may only duplicate raw
Host exactly. A differing value, list or port fails closed. No forwarded hostname
establishes identity and no trusted reverse-proxy deployment is activated.
GET/HEAD navigation may omit Origin; supplied Origin must match exact HTTPS Host.
Every browser mutation requires exact same-host HTTPS Origin. Supplied
Sec-Fetch-Site must be same-origin or none. Reserved platform subdomains, internal
domains and malformed hostnames fail closed.

OTP request/verification, explicit refresh and logout use a bounded JSON BFF
route. Credentials never return in browser JSON or SSR HTML and never enter
sessionStorage. The __Host-aaraagate-partner cookie has Secure, HttpOnly,
SameSite=Strict and Path=/ with no Domain attribute. AES-256-GCM authenticates the
encrypted credentials with hostname-specific associated data, so even manual
cookie copying to another partner host fails. Cookie key rotation forces sign-in.
Refresh is explicit, never a side effect of rendering, preserving the existing
refresh-replay detection. Concurrent explicit refreshes may require sign-in again.

The API host-session endpoint reuses persisted SessionService validation and
rejects unbound partner, standard/society and operational principals. Its derived
partner ID and hostname must match the sealed cookie before SSR reads the scoped
portfolio. The portfolio guard revalidates current domain claim/version,
membership and licensed capacity again. Expiry, claim withdrawal, changed
authority or revoked access returns the sign-in recovery state without portfolio
data. Existing platform and society login flows remain separate.

Browser responses include no-store/private, Vary: Host, Origin, Cookie,
no-referrer and nosniff. Upstream requests never forward browser cookies, follow
redirects or choose a client-supplied URL. Upstream responses and request bodies
are bounded and upstream I/O has a ten-second deadline.

## Acceptance and limits

Local focused API regressions passed 33 tests. Behavioral cookie/policy tests
cover copied/tampered/expired cookies, wrong keys, reserved hosts, spoofed proxy
headers, Origin and production-disabled behavior. The actual Next dev-server
HTTP acceptance covers canonical navigation, authenticated SSR, credential
non-disclosure, society/platform denial, cross-host copying, cookie attributes,
OTP issuance, explicit refresh/logout and revoked access. This uses a local API
double; existing API behavioral and native PostgreSQL tests establish persisted
authority. Protected CI runs the actual Next acceptance before Admin integration.
Protected CI and develop integration remain pending until recorded by GitHub.

This slice does not claim public DNS/TLS activation, trusted proxy sanitization,
browser HTTPS deployment acceptance, branded Android distribution, full V5
closure, or staging/main promotion. Disable the web flag and invalidate/revoke
bound sessions before older application rollback, as required by V5.4.17.
