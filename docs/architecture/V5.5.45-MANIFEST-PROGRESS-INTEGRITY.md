# V5.5.45 — V5 release manifest progress integrity (nonproduction)

Baseline: `develop` `353a1d4ca9d63e068c11bf6558b134cdcbe33479` (Services 4.4.2, PR #1377 merged). Prior TEST Linux observer V5.5.44 PR #1354 and required protected CI had already merged.

## Root cause and scope

The checked-in V5.5 milestone had correctly recorded V5.5.44 with protected evidence, but `currentSlice` still pointed to V5.5.37. Resuming from that stale pointer risks repeated work and misleading progress reports. V5.5.45 updates `currentSlice` to the latest registered slice and adds an auto-discovered, offline repository integrity check. It makes no API, tenant inventory, schema, Android wrapper, host routing, runtime observer or CI workflow YAML changes.

`scripts/v5-manifest-progress.mjs` enforces:
- V5 stays `IN_DEVELOPMENT` with `productionizationIncluded:false`; only `develop` is the slice target and `staging`/`main` promotion retain their separate approval gates.
- `V5.5.currentSlice` equals the latest unique, strictly increasing `V5.5.n` slice in the release manifest, so a newly appended slice requires pointer reconciliation.
- V5.5 remains `IN_PROGRESS`, the independently trusted TEST runner blocker remains explicit, and V5.6 remains `PLANNED`. This gate must intentionally be revised after **independent** remote acceptance evidence before program status can change.
- Pure receipt outputs always report Android execution and partner artifacts as unauthorized/unverified, regardless of passing manifest tests.

`scripts/v5-manifest-progress.test.mjs` includes positive checked-in and negative tamper cases for stale/future pointers, duplicates, out-of-order slices, erased external blocker, false completion, productionization and unapproved branch promotion. `scripts/check-v4.79.1.17-v5-manifest-progress.mjs` joins the existing auto-discovered Repository structure checks and runs only Node built-ins. It does not launch Android or multiply the full CI suite.

## Hard external blocker remains

This is **checked-in metadata integrity, not third-party runtime evidence**. V5.5.36–44 demonstrate increasingly strict *offline* claims and local target-process checks, but no independently operated external TEST observer/worker has authenticated and measured the live OCI image, registry layers, process/immutable mounts and one-time transport challenge. Real TEST Partner A/B app signing/build, co-installation, rollback and V5.6 release acceptance remain pending.

Status upon PR submission: `PENDING_PROTECTED_CI`. Merge to `develop` only if the protected repository/API/Admin/Flutter/security gates complete successfully. Record PR/CI evidence after acceptance; do not claim passing gates or promote to staging/main in advance.
