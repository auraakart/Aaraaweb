# V5.4.15 — Local web Host/Origin preflight contract

Scope: pure non-production contract and negative tests. It does not introduce Next.js middleware, real DNS routing, TLS, database reads or host-bound sessions.

The verifier uses only the raw server Host; refuses nonempty forwarded-host claims; requires an exact HTTPS Origin on the same canonical hostname; reserves platform hostnames; and previews only unique, verified, nonexpired fixture records. Candidate output is marked routingActivated=false and sessionBound=false.

previewSessionHostMatch documents future persistent session binding requirements; V5.4.14 commercial bearer sessions have no such binding and therefore cannot satisfy the contract. A future implementation must validate a server-persisted audience, origin host and partner ID; use trusted proxy configuration and host-only cookies; and pass SSR cross-host isolation tests before routing can activate.

The contract exposes no account data, grants no membership, never interprets a brand as permission, and specifies no-store/private and Vary: Host, Origin for future browser responses.

Protected CI runs scripts/partner-host-boundary.test.mjs alongside the existing V5 domain contract tests. Future V5.4 slices still need actual authenticated multi-host SSR acceptance, host-bound session persistence and approved distribution controls.
