# V5.4.14 — Dedicated commercial partner OTP sign-in

Non-production scope. Reuses Aaraagate's existing rate-limited OTP request and one-use verification store; **does not create a second identity database or grant a society operational role**.

`POST /api/v1/auth/partner/otp/verify` requires a verified OTP and an ACTIVE user with either an active PartnerMembership for an ACTIVE partner or a current unexpired pending PartnerInvitation for an ACTIVE partner. It creates a society-less Session with empty AppRoles. It returns no partner roster, society data or contact details. The existing resident and Admin OTP responses remain unchanged.

`/partners/login` is the dedicated sign-in page. Browser tokens are stored under `aaraagate.partner.session`, not `aaraagate.admin.session`, and are never copied between the two. Partner pages prefer the dedicated session, then accept a legacy admin session for compatibility. Refresh/logout use an audience-specific session storage key; per-origin browser storage prevents cross-domain token sharing. UI does not claim production host-bound cookies or SSR host isolation.

The existing scoped partner portfolio and invitation APIs recheck authority on every call, so role revocation removes access without treating a partner token as a society grant. Invited user can open the member inbox and accept an invitation before obtaining an active partner role.

Acceptance: no partner login to society operations; forbidden user/inactive partner denied; partner-only and invited users supported; secure storage isolation tests; full protected CI.
