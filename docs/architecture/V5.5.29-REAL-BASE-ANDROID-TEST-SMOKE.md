# V5.5.29 — Real base Resident/Guard Android TEST smoke

Baseline: V5.5.28 PR #1319 merged into `develop` at `2761922291bf4fce083d0e9afc546c20da6cf151`; protected validation run 38620432410 succeeded.

A new narrow GitHub Actions job builds **actual debug APKs** of the existing Aaraagate Resident and Guard source, separately, using Flutter 3.47 and Java 17 in ephemeral GitHub hosted runners. It generates each default Android wrapper, restores reviewed tracked Dart files, pins compileSdk 36/minSdk 24/targetSdk 36, resolves dependencies and compiles debug-mode APKs.

After build, a role-limited script checks ZIP integrity, AndroidManifest.xml, classes.dex and ARM64 engine, expected default applicationId, SDK levels, installed SDK apksigner v2 verification and signer fingerprint presence, and records SHA-256 and byte length. Debug APKs and bounded evidence are retained for **1 day**. The workflow runs only on changes to its two smoke-workflow files on `develop`, or manual workflow dispatch there; it does not run on every PR.

**Scope:** This is a real build smoke of DEFAULT `com.aaraaplatforms.aaraagate_resident` and `com.aaraaplatforms.aaraagate_guard` debug identities, not partner-specific or customer distributions. Android SDK binaries are locally used, not independently SHA-pinned; Github-hosted runners are not independently attested V5 TEST workers. No server-side build dispatch, commercial approval, partner manifest binding, custom signing, production credentials, real device co-installation, store publishing, staging or main promotion. No release-grade provenance is claimed.

Do not mark successful artifacts until the first actual post-merge GitHub workflow demonstrates both roles passed. A broken debug build needs a narrowly scoped follow-up fix. Subsequent V5.5 tasks must separately run the approved partner manifests in attested isolated TEST workers and verify real APK/AAB outputs, identities and signing provenance before V5.6 acceptance.
