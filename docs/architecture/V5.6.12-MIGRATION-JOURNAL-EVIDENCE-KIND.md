# V5.6.12 — Opening-balance migration evidence kind integrity

**Baseline:** V5.6.11 PR #1392 merged into `develop` at `bb71a893b669c5473623b322fb5ffdfa63f67b34` with required checks green.

## Gap

Opening-balance migrations write `MigrationBatchRow.targetType='JournalEntry'` and `targetId` together. Previous rollback and already-COMMITTED replay checks required complete, valid rows targeting one existing POSTED journal from the correct society/batch, but did not verify the stored **targetType**. A row whose `targetId` still referenced a journal while `targetType` had been changed to a different resource type would be silently accepted as valid recovery evidence.

## Fix

Read `targetType` with `targetId` in the existing loadRows queries. During already-COMMITTED replay and during rollback preflight, require each row to have `targetType === 'JournalEntry'` as well as the prior validity, complete count, unique ID and exact source matching. A mismatched type fails closed with the existing migration-evidence conflict message before journal reversal or batch mutation. No database schema or public API changes.

Add two unit regressions for mismatched resource kinds during committed replay and rollback, verifying the accounting reversal is not attempted and the mutation transaction stops at evidence lookup. Existing PostgreSQL concurrency, atomic fault-recovery and journal-source provenance regressions remain required.

This does **not** claim production readiness, signed Android/Partner A/B acceptance, physical TEST runner commissioning or V5.6 release closure. All protected CI checks must pass before merging to `develop`; `staging` and `main` stay untouched.
