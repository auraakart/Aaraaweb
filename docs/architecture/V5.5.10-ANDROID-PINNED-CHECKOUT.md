# V5.5.10 — Pinned TEST Android checkout preflight

Baseline: V5.5.9 PR #1300 merged into `develop` at `ba2043ff2168057a4da13dc4e753730d9f7015aa` after required protected CI passed.

A small new `verifyPinnedTestAndroidCheckout` helper verifies an already provided **local, isolated, clean Git checkout** before a future TEST Android worker can use the V5.5.9 staged native inputs. It compares the exact Git HEAD SHA and SHA-256 of the actual `pnpm-lock.yaml` bytes against immutable reviewed Android TEST manifest pins and independently supplied expected values. It requires the repository top-level directory, rejects symlink checkout roots, untracked/dirty files, non-regular lockfiles, extra input keys and non-TEST/non-dispatchable plans. Git is invoked through `execFile` without a shell, with a bounded timeout/output and hardened Git environment. Resident and Guard contracts use fresh ephemeral Git repositories and verify failure states.

## Explicit limitations and follow-on gates

The verification proves only **local content consistency with expected pins**, not the legitimacy of the values supplied as pins, of the Git remote, or the identity of the invoking worker. Expected values and checkout root **must come from a separately authenticated and authorized worker control plane**, never a partner request or client header. This helper does not clone/checkout, authenticate a worker, verify Android/Flutter/Java toolchains or template provenance, materialize a native wrapper, execute Gradle/Flutter, handle secrets, sign binaries, publish artifacts or claim archive verification. Output is always `dispatchAllowed: false`, `artifactProduced: false`.

Next: independently authenticated isolated runner transport and template/toolchain pin verification; apply the staged Kotlin/Gradle/manifest files to a real generated Flutter 3.47 Android wrapper with Android 12 splash integration; recheck dispatch authority, run bounded TEST builds, independently inspect signed APK/AAB, reauthorize completion and record immutable provenance. Never modify existing demo/release flows or stage/main within this slice.
