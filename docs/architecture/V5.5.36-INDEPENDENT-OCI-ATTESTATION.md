# V5.5.36 — Independent OCI TEST worker image signature preflight (non-dispatch)

Baseline: `develop` `b061175df9bcbb79bcc2f29d341e1e10b4637c51` after V5.4.24 closure evidence. V5.5.35 CI regression guards remain active.

## Implemented

A reusable pure verifier at `packages/config/src/android-test-oci-provenance.mjs` checks a **DSSE envelope** carrying an explicitly versioned `application/vnd.aaraagate.test-oci-image-claim+json` statement. It requires Ed25519 verification against a separately and independently **operator-pinned attestor public key**, with a distinct pinned worker signing key. The signed payload must match the TEST OCI image SHA-256 descriptor, exact reviewed source commit SHA, worker ID, run ID, attestor ID, and server challenge nonce. It enforces exact payload/policy field sets, canonical JSON/base64url, correct DSSE PAE, one signature, strict UTC windows and short expiry; no self-selected keys or claims are accepted.

The new module **does not** call registries, issue Docker commands, run a Flutter or Android build, grant credentials or dispatch a worker. Both keys in CI are ephemeral fixture keys, NOT the independently reviewed trust roots needed for an actual deployment. The signature verifies only a signed *claim*, not the **actual OCI image bytes** or which image a worker is running.

`scripts/android-test-oci-provenance.test.mjs` exercises 15 success/failure tests, including source/digest drift, different signer, reused nonce/run identities, wrong worker/builder, signing-key reuse, malformed envelopes and expired/prod claims. The auto-discovered `scripts/check-v4.79.1.8-v5-oci-attestation.mjs` runs the test in the existing Repository structure job; `.github/workflows/ci.yml` is unchanged.

## Authority and future acceptance

The verifier's result deliberately has `runtimeImageAttested:false`, `actualOciImageBytesVerified:false`, `runtimeTransportAuthenticated:false`, `registryDigestVerified:false`, `singleUseChallengeConsumed:false`, `buildExecutionAuthorized:false`, `artifactProduced:false` and `dispatchAllowed:false`.

Before any partner-specific TEST build, provision an independently authenticated test worker/attestor, review and pin independent attestor key custody and OCI descriptor digest, verify the registry manifest against that exact digest, bind a live authenticated transport/challenge to the running isolated process and atomically consume the nonce, pin source/toolchain/SDK trees and validate an approved reservation. Only after those checks may a separately reviewed execution authorization be designed; **this preflight does not provide that authority**.

V5.4 external ingress, V5.5 trusted real runner and Partner A/B APK/AAB, and V5.6 acceptance remain open. Productionization and `staging`/`main` promotions are excluded.
