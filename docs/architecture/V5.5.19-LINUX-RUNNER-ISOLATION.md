# V5.5.19 — Linux isolated TEST-runner confinement policy

Baseline: V5.5.18 TEST-only TLS 1.3 pinned mTLS identity probe merged into \`develop\` as \`ca271f3d903cb08e63caf58cc83810c0f8e3b55b\`, protected CI run \`38593459234\`.

The new library validates a **local Linux kernel** security-boundary observation: a non-root single UID/GID, all five Linux capability sets empty (inheritable/permitted/effective/bounding/ambient), \`NoNewPrivs: 1\`, \`Seccomp: 2\`, at least one seccomp filter, and four exact separately pinned read-only, \`nosuid,nodev\` SDK and template mounts. It denies absent/multiple mountpoints, read-write mounts, untrusted backing/filesystem, nested overmounts that could obscure verified trees, symlinked paths, special/oversized proc data, unexpected control values or stale identities. Production API reads live \`/proc/self/status\` and \`/proc/self/mountinfo\`, checks real paths and file types, and requires prior TEST-only signed evidence acceptance, pinned TLS server/worker handshake, plus V5.5.16 complete local SDK/tree bytes. The pure parser is separately unit-tested with synthetic kernel snapshots; tests **do not** claim to have run in a provisioned isolated environment.

**Critical caveat:** Linux mountinfo and status are local observed facts, and a self-reported container image digest remains only a claim. This slice is not a cloud/host-issued, independently verified OCI runtime quote, not a hardware-rooted trusted-execution attestation, not proof of read-only immutable execution for an entire process lifetime, and not a physical remote runner deployment. It explicitly returns \`runtimeImageAttested:false\`, \`immutableMountVerified:false\`, \`buildExecutionAuthorized:false\`, \`artifactProduced:false\`, and \`dispatchAllowed:false\`. The next phase must provision a separately trusted runner, independently attest the running image digest and immutable mounts, and implement a one-use server authority transition for actual TEST build dispatch/completion; never treat this preflight as permission to compile, sign or distribute Android artifacts.

The module does not accept HTTP-supplied /proc snapshots for live verification, does not execute commands, does not provide new routes, does not manage secrets, does not perform APK/AAB operations, and does not alter staging or main. Protected CI and reviewed changes precede squash merge to develop.
