# V5.5.4 — Isolated TEST Android resource overlay

Baseline: V5.5.3 PR #1294 accepted in protected CI #38543744066 and squash-merged to develop at `ca3bb72e64d5602019362c95f795c3a2202bb824`. No staging/main modification.

## Intent and non-capabilities
Prepare non-executable Android native inputs from the existing V5.5.1 build plan and V5.5.3 append-only reserved `versionCode`. This slice **does not run** `flutter create`, `gradle`, `flutter build`, a signing command, GitHub Actions dispatch or publication, and does not claim a tested APK/AAB. Existing Resident and Guard app source trees are not modified. The historical demo's package or signing identity remains untouched.

## Narrow implementation
`materializeTestAndroidResourceOverlay(plan,reservation,{icon,splash})` writes only a fixed-list, throwaway file structure under a newly generated OS temporary directory:
- `android/app/src/main/res/drawable-nodpi/aaraagate_test_icon.png`
- `android/app/src/main/res/drawable-nodpi/aaraagate_test_splash.png`
- `.aaraagate/test-build-input.json`

Inputs require a bounded TEST plan with exact canonical digest, a matching immutable, non-dispatchable reservation with a positive Android version code, and two in-memory asset byte arrays that match approved SHA-256 digests (2 MiB limit each). A basic PNG signature/IHDR/dimension sanity check prevents obvious non-PNG and extreme dimensions. This **is not** a PNG decoder/sanitizer; the trusted branding pipeline must have completed full sanitization before permitting bytes to reach this step.

Metadata records approved source/lock and config digests, immutable applicationId/namespace/role, reserved versionCode, TEST signer reference/fingerprint, disabled push, app-link hosts and resource digests. It explicitly marks `dispatchAllowed:false`, `artifactProduced:false`, `archiveVerified:false`, `requiresNativeManifestPatch:true`. No private signing key or Firebase credentials are accepted or written.

All paths are constant except the random OS temporary root. The helper never writes into `apps/resident`, `apps/guard`, or Git-tracked source; on write error the temporary directory is removed. **The caller must remove the returned directory in `finally`**, because this API deliberately cannot take arbitrary user-selected output paths.

## Acceptance and next boundaries
Existing CI runs `node --test scripts/android-build-contract.test.mjs`; its additional cases cover both Resident and Guard overlays, exact file content, metadata denial flags, cleanup, version/digest mismatch, expired/foreign shape rejection and PNG header denial. Require repository-structure, API/Admin/Flutter/security merge gates. No synthetic successful artifact or app-store readiness is implied.

Later slices must use a **trusted** server-side snapshot, revalidate live licensing and immutable revisions at dispatch and completion, verify published branding/asset sanitization, produce a bounded isolated Flutter/Gradle wrapper pinned to Java 17, Flutter 3.47.0, Node 22 and pnpm 10.15.0, patch native identity safely, verify TEST archive/ABI/signatures before recording real immutable provenance. A version reservation or overlay alone is not build authorization.

Rollback: remove the overlay helper/export/test only; preserve reviewed revision and version reservation ledgers permanently. No new migration and no default demo build workflow change.
