# V5.4 nonproduction engineering acceptance

V5.4 licensing backend and Admin controls are merged into develop. V5.4.7 completes the proposal immutability, test-domain request context and additive-schema rollback regressions. This scoped licensing/control-plane acceptance is complete after protected CI and develop merge; the broader V5.4 partner portal milestone remains in progress. The broader V5 program remains in development.

## Implemented scope

Commercial proposals and revisions, independent scoped Super Admin approval, append-only revocation, explicit society opt-in/withdrawal, and serialized allocation are separate immutable records. Approval is authority, rather than a mutable GRANTED proposal flag. Selected-society authority, active ownership history, legacy tier/overrides/features and current consent are revalidated on writes and idempotent retries. Domain candidates require current approval and allocation. Existing PartnerMembership portfolio reads expose bounded non-PII metadata without operational role elevation.

Admin licensing controls reuse the current authenticated society session and shared UI. Separate approval, consent and activation steps retain retry keys, cancel stale reads and discard responses from older sessions. Society administrators cannot see partner-wide capacity usage or perform platform mutations.

Unapproved proposal terms are now immutable from creation using the existing update trigger and an additive replacement function migration. Correcting or renewing terms creates a new proposal. Existing immutable history is retained.

## Domain request acceptance

The authenticated `/licensing/societies/:societyId/domain-context` adapter reads the raw Host header through Express `header('host')`, never forwarded-host authority. It reuses the same hostname contract and authorization as domain-preview. Both require test/development mode, explicit opt-in environment flag, bounded configured verified registry, exact current partner/society ownership, current approval/allocation, and domain ceiling. The response reports RAW_HOST and remains testOnly, candidateOnly, routingActivated=false. Foreign partner/society hosts, unregistered/reserved/invalid hosts, registry withdrawal and license revocation are denied. Removing the registry disables candidates; restoring it recovers cosmetic inspection subject to renewed checks.

No Host or query parameter selects the authenticated society or grants permissions. This is not a public partner login surface, production routing, DNS challenge verifier or cookie configuration.

## Rollback acceptance

The native PostgreSQL rehearsal invokes the unchanged legacy entitlement resolver and DRAFT persistence reader/writer against the additive approved-licensing schema. It verifies unchanged compatibility snapshots and exact legacy features after opt-in/allocation. A legacy DRAFT reservation remains a rehearsal receipt and cannot bypass the approved active-license capacity. Proposal edits are rejected even before approval. Existing concurrency, failure rollback, expiry/grace, withdrawal, revocation and stale-authority tests remain mandatory.

Operational rollback retains all additive tables and immutable history; do not drop approval, consent, ownership or allocation records. Disable the test registry/flag, stop new licensing writes and use the approved previous application revision after validating against this additive schema. This evidence is a database/application compatibility rehearsal, not a hosted release rollback drill. Gate/SOS and existing features continue through the unchanged legacy resolver.
