# V5.5.2 — Immutable TEST Android revision persistence and independent review

Baseline: `develop` at `aa35252c69f0ff2b48b968ab6908887bd980c26f` (V5.5.1 PR #1292 merged, 13/13 required CI jobs green).
No staging/main changes, no productionization, signing or artifact generation.

## Reuse and scope
Use V5.4.20's immutable distribution proposal, separately approved identity and current licensed allocation transaction. Do not create independent login, licensing, branding or partner authority. The **original applicationId, namespace, role and test signing-profile reference** remain unchanged for app-update continuity. New reviewed revisions may carry updated pinned source, dependency lock, label, published-brand reference, sanitized TEST resource digests and public TEST mappings; none is trusted simply because a client supplied it.

Data is append-only: `PartnerAndroidBuildRevision` has a per-distribution monotonic sequence, canonical SHA-256 digest and idempotency key. `PartnerAndroidBuildRevisionApproval` records independent live-super-admin review. The PostgreSQL insert triggers recheck licensing/active context, society/partner/identity, maker/checker, latest version, update signer continuity and append-only history. Two proposals cannot race to assign the same version: both use the existing grant/society authority and a row lock on the immutable distribution proposal. No new revision is allowed while the latest lacks review.

## API
All three endpoints are POST, no-store, BearerGuard + RolesGuard SUPER_ADMIN, under the existing society-scope `/api/v1/licensing/societies/:societyId`:

- `distributions/:proposalId/android-revisions`: propose exactly one immutable 20-field TEST build manifest. Returns digest/version and **dispatchAllowed:false**.
- `distributions/:proposalId/android-revisions/:revisionId/approvals`: independent approved exact digest and reason; maker/current authority and latest revision are revalidated.
- `distributions/:proposalId/android-revisions/latest-reviewed`: reauthorized latest-only retrieval. Returns **requiresBuilderRevalidation:true** and **dispatchAllowed:false**. An unreviewed newest proposal blocks retrieval, rather than silently falling back to stale older approval.

All requests use the existing `grantId`, `allocationId`, expected grant/ownership versions and UUID idempotency keys. Unknown manifest keys, unsafe paths/labels, non-TEST signing, foreign partner/society/role, reserved Android identity, unallowlisted HTTPS API origins, signer drift and expired/revoked licensing fail closed. No credentials or signing keys are stored. A reviewer of one revision cannot edit an earlier immutable revision.

## Evidence and limitations
Unit and native PostgreSQL regression cover replay, two-operator approval, signer continuity, tenant ownership, revoked authorization, direct SQL constraints and append-only records. Required full API/Admin/Flutter/dep/security gates must pass before merge. **No approval authenticates raw source SHA, published brand/assets, verified custom domains, Firebase clients, app signer, archive or actual bytes**. A future trusted builder must re-resolve all persisted facts and recheck grants/approvals at dispatch AND completion, reserve monotonic Android `versionCode`, verify produced APK/AAB signatures and publish immutable provenance. Thus V5.5.2 does not mark an app build-ready for execution.

Rollback: disable new revision routes/readers. Preserve immutable revision/review rows and signer history; never truncate or reallocate an application identity. The existing V5.4 distribution and default V4.91.5 Resident demo remain authoritative/unchanged. Next: V5.5.3 versionCode allocator/job ledger, then disposable wrapper generation and on-demand bounded TEST artifacts.
