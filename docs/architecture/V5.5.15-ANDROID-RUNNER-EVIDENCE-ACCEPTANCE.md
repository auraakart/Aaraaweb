# V5.5.15 — Atomic signed TEST runner response acceptance

Baseline: PR #1305 V5.5.14 merged into develop as `acd0329e6e097e0e7dbc4baba3224efaa136884d` with protected CI green.

This slice adds an internal-only acceptance service and append-only SQL/Prisma proof ledger. On an independently configured TEST Ed25519 public key, the service cryptographically verifies the exact V5.5.13 domain-separated canonical signed statement, checks its source, lock, worker, image-policy claim, distribution, reservation, consumed claim, build revision, version, run ID, server-issued nonce digest and 60-second challenge window, and rechecks live license authority before DB insertion. DB triggers independently recheck current allocation, approval, newest independently reviewed TEST revision, challenge/claim/worker/version, expiration, source/lock; unique indexes enforce **one acceptance per challenge**, run ID, nonce digest and signature digest, preventing concurrent replay. No signing key or plaintext nonce is persisted.

Native / toolchain digest values in the statement are **signed worker claims**, not independent remote proof those inputs were read. The accepted receipt still returns runnerTransportAuthenticated:false, runtimeImageAttested:false, flutterSdkTreeVerified:false, artifactProduced:false, dispatchAllowed:false. There is no HTTP route, automatic build, signing, APK/AAB or release promotion. Provision the worker identity, public key, runner image digest and independently trusted transport out of band; subsequent slice must verify the complete SDK/image/template and provide isolated execution before changing the non-dispatchable status.

Validate clean PostgreSQL migrations, native DB constraints, API typecheck, scoped Vitest and protected CI. No staging/main or default demo APK changes.
