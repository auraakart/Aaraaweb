# V5.5.46 — Operator-only TEST runner evidence probe

## Background and precise boundary

Finance issue #1387 is complete on `develop`: PR #1401 (V5.6.20) regenerated the full tenant-access inventory and passed CI #38932019095, and PR #1402 (V5.6.21) reconciled closure with protected CI #38932916001. That issue is no longer the cause of V5 acceptance delay.

The remaining issue [#1380](https://github.com/auraakart/Aaraaweb/issues/1380) is **independently provisioned** TEST worker / OCI provenance and Partner A/B Android acceptance. Existing `packages/config/src/android-test-oci-runtime-transport.mjs` supports read-only pinned TLS 1.3/mTLS and Ed25519 signed-claim validation, but repository CI tests simulate the endpoint and **do not establish a real independent worker**. This slice exposes that already-reviewed verifier to an external TEST operator without enabling a build or granting trust automatically.

## Operator prerequisites (not created by this repository)

An independent authorized TEST operator must provide an isolated worker/observer, separate Ed25519 attestor/worker/observer public-key trust pins, a genuine immutable OCI image/source record, a dedicated TLS 1.3 TEST endpoint at `/v1/test-runner/runtime-evidence`, a pinned server certificate key and a separate read-only client certificate and private key. This is not a command to provision production infrastructure. The signed image claim must be independently checked; **signed claims are assertions, not independent container/mount measurements**.

Place the JSON evidence files and CA/client certificates **outside** the Git checkout; never commit private keys. Create a private absolute-path plan JSON outside the checkout:

```json
{
  "schemaVersion": 1,
  "environment": "TEST",
  "purpose": "READ_ONLY_RUNTIME_CLAIM_PROBE",
  "imageEnvelopeFile": "/secure/test/image-envelope.json",
  "imagePolicyFile": "/secure/test/image-policy.json",
  "runtimePolicyFile": "/secure/test/runtime-policy.json",
  "transportPinsFile": "/secure/test/transport-pins.json",
  "caCertificateFile": "/secure/test/test-ca.pem",
  "clientCertificateFile": "/secure/test/client-cert.pem",
  "clientPrivateKeyFile": "/secure/test/client-key.pem"
}
```

`transport-pins.json` has **exactly** `endpoint`, `serverName`, `serverSpkiSha256`, and `clientSpkiSha256` fields (without PEM secrets). The image policy and runtime policy use the exact schemas already enforced by the existing cryptographic validators. Source SHA, image digest and endpoint must match independently approved operator environment pins. Each referenced file must be regular, unique, absolute, non-symlink, and outside the repository; client key permissions must exclude group/other access (for example, `chmod 600 /secure/test/client-key.pem`).

## Explicitly approved read-only invocation

Use an independently controlled TEST shell, not CI or the application runtime:

```bash
export NODE_ENV=test
export AARAAGATE_V5_TEST_RUNTIME_PROBE_CONFIRM=I_APPROVE_READ_ONLY_TEST_RUNTIME_PROBE
export AARAAGATE_V5_APPROVED_TEST_RUNTIME_ENDPOINT=https://test-runner.example.org/v1/test-runner/runtime-evidence
export AARAAGATE_V5_APPROVED_TEST_SOURCE_SHA=<exact-reviewed-40-character-source-commit>
export AARAAGATE_V5_APPROVED_TEST_IMAGE_DIGEST=sha256:<exact-reviewed-64-character-image-digest>

node scripts/v5.5.46-run-readonly-runtime-probe.mjs /secure/test/operator-plan.json
```

Replace placeholder pins with the operator's actual independently reviewed TEST values. The command performs one **read-only** evidence probe through the existing library and returns only a fixed non-secret summary of TLS peer and signed-claim validity. No CI workflow automatically calls the probe, no APK builder is invoked, and no signed claim can grant `buildExecutionAuthorized`, `artifactProduced`, `dispatchAllowed` or `singleUseChallengeConsumed`.
