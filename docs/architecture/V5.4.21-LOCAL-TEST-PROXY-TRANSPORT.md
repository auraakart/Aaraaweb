# V5.4.21 — Fixed-upstream local TEST ingress and forwarded-header acceptance

Baseline `develop` `d07cfdcadbbbb6af0dc3709f353e8a7d02f7a67f` after V5.6.1 PR #1329 and protected CI #38682026137.

This slice makes an **actual local HTTP transport** integration test for the existing V5.4.18 direct-Host Next SSR/cookie boundary, without enabling reverse-proxy trust in the application.

`scripts/check-v4.79.1.5-v5-local-proxy-transport.mjs` opens **only loopback** ephemeral HTTP listeners as a test-only front proxy and simulated upstream. The proxy routes to one fixed `127.0.0.1` server independent of browser Host; it preserves exact canonical allowlisted raw Host, writes `X-Forwarded-Host` as the *same* Host, rejects injected `Forwarded`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-For`, `X-Real-IP`, `X-Original-Host` and `X-Original-URL`, validates mutation Origin and Sec-Fetch-Site, bounds the body and upstream reply, enforces no-store/private, Host/Origin/Cookie Vary, and blocks foreign absolute redirects. Negative tests assert rejected messages never reach the backend.

The existing Next host policy still derives its presentation from **raw Host only**. Proxy headers are not authorization, the upstream URL never comes from Host, and no partner/society/session may be selected without application authorization. A test dummy demonstrates that copying an untrusted cookie cannot establish a second partner session; **it does not prove the real Next cookie cipher or actual browser behavior**. Those separate V5.4.18 contracts remain in place.

## Evidence boundary and follow-up

The check runs through the existing `scripts/check-v4.79*.mjs` auto-discovery in protected Repository structure: no edits to `ci.yml`, no redundant Android builds, no new API/Web route. It is *local HTTP* and does **not** establish public DNS, a trusted TLS-terminating ingress, network provenance, remote IP trust, live browser HTTPS acceptance or production authorization. The manifest's V5.4 trusted reverse-proxy acceptance remains open pending separately provisioned and validated ingress. It is a preparatory engineering slice, not V5.4 milestone closure.
