# V5.4.11 — Inert partner domain claim registry

**Scope:** Development-only additive pending registry in the existing Aaraaweb monolith. No DNS verification, host routing, TLS, cookies or distribution activation is implemented by this slice.

## Contract and authority

- \`POST /api/v1/partners/:partnerId/domains\` accepts \`{hostname,idempotencyKey}\`; only a current active OWNER membership under an ACTIVE partner can register. Authorization is checked inside a partner-row-locked transaction.
- \`GET /api/v1/partners/:partnerId/domains\` is owner-scoped, limited to 50 non-sensitive claim summaries, with \`hasMore\`.
- Strict IDNA canonicalization and reserved platform hostname policy reuse \`@aaraagate/config/partner-domain-loader\`. The platform must configure \`AARAGATE_PLATFORM_HOSTNAMES\` with its reserved public hosts.
- A new claim is \`PENDING\` only, globally unique by hostname, with a maximum of five claims per partner and an immutable registration event. This is a safety limit pending commercial domain-capacity enforcement.
- The returned random challenge is shown **once**; only its SHA-256 digest is stored. An exact idempotency replay returns \`challenge:null\`, and changed replay input is rejected. The challenge is not an authentication credential.
- No \`PENDING\` claim is passed to hostname presentation resolution. \`VERIFIED\` state is reserved for a later independently verified, auditable action. Production routing remains disallowed.
