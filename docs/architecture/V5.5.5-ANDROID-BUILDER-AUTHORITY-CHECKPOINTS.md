# V5.5.5 — Live TEST Android builder authority checkpoints

Baseline: V5.5.4 PR #1295, protected CI #38548511220, merged into `develop` at `aaa4b77a6d90bd5c352b144d5feb098b8e286fe4`.

## Security boundary

An immutable versionCode reservation is **not** a build permit. This slice adds `PartnerAndroidBuildReservationService.checkpoint`, a **read-only**, fail-closed server authority check intended for a future isolated builder to invoke at two distinct trust boundaries: `BEFORE_DISPATCH` and `BEFORE_COMPLETION`. Both calls must use newly obtained live authority; a successful prior response must never be cached or treated as a worker credential.

Each checkpoint uses the existing authenticated society `SUPER_ADMIN`-scoped live allocation helper, which rechecks current ownership version, partner, active commercial license, consent, effective entitlements and allocation. It locks the targeted distribution row and independently loads the current distribution approval (including revocation), the latest independently reviewed immutable TEST revision, and the exact append-only versionCode reservation. It checks the initial and reviewed manifest canonical digests, reservation linkage and versionCode, society/partner/approval identity, TEST role, and immutable initial package, label, source, brand config, API origin and test signer profile fields.

The response is deliberately `CURRENT_TEST_AUTHORITY_ONLY`, `testOnly:true`, `dispatchAllowed:false`, `artifactVerified:false` and `requiresIndependentWorkerVerification:true`. It is **not** a signed token, queue dispatch, successful archive check, persisted completion evidence or privilege delegation. The existing reservation API does **not** call a build worker and no public checkpoint API route is added.

## Acceptance

Targeted Vitest cases validate both independent stages, revocation, stale or superseded revision, foreign/changed reservation, invalid request shape, changed immutable identity, digest tampering and current licensing failures. Required repository/API (including PostgreSQL)/Admin/Flutter/dependency/security gates must pass before merge to develop.

No Prisma migration is introduced, and `docs/architecture/v5-tenant-access-inventory.json` must be reconciled if the inventory checker detects changes to a Prisma-access symbol. Only `develop` is eligible for this slice.

## Unfinished work

A separate trusted worker identity and scoped single-use execution lease, real-time checkpoint integration at dispatch and completion, immutable source/lock and sanitized asset attestations, pinned toolchain, ephemeral Flutter Android wrapper and manifest/Gradle patch, actual test signing/inspectable APK and AAB, archive verifier and immutable artifact provenance are still outstanding. Both checkpoint calls remain necessary even after those facilities exist.

Rollback may remove only this read-only helper and tests; preserve all immutable revision and reservation history.
