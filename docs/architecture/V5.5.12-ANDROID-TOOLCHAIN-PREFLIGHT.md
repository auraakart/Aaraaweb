# V5.5.12 — Locally pinned Android TEST toolchain preflight

Baseline: V5.5.11 PR #1302 merged into develop at 2e82812a58123a26f9dda8967644b51f261dcfa1 after protected checks passed.

This slice verifies local executable file SHA-256 and actual version responses for four fixed TEST toolchains: Flutter 3.47.0 stable, Java 17, independently pinned Node 22.x patch, pnpm 10.15.0. The caller must already operate inside an isolated worker with canonical non-symlink executable paths and expected byte hashes supplied from a separately trusted runner policy. Commands use explicit execFile arguments, no shell, a scrubbed environment and bounded time/output. Resident/Guard contract tests run disposable synthetic executables and exercise tampering, stale checkout, untrusted version pins, invalid paths and forbidden dispatch flags.

Security limitations: Hashing individual launchers and querying versions cannot authenticate a worker, attest the complete Flutter/Android SDK or prove generated template identity. File races remain until immutable mounts/worker image policy. Since version commands execute programs, never accept executable paths/hashes from partner configuration or HTTP input. A future separately authenticated runner must supply independently trusted executable hashes. The result explicitly keeps runnerAuthenticated, flutterSdkTreeVerified, androidSdkVerified, artifactProduced and dispatchAllowed false.

No real Flutter/Gradle builds, test signing, APK/AAB, external provider integration, API/Prisma changes, staging/main promotion or changes to default demo workflows.

Next: authenticate runner identity tied to one-time worker consumption and immutable build inputs, verify pinned complete SDK/templates, then generate Android wrapper, integrate styles/Android 12 splash, build under bounded execution and inspect signed archives before completion provenance.

Validation: node --test scripts/android-build-contract.test.mjs and required protected GitHub checks.
