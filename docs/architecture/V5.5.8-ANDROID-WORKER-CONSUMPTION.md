# V5.5.8 — Single-use TEST worker consumption and completion authority

Baseline V5.5.7 [PR #1298](https://github.com/auraakart/Aaraaweb/pull/1298), green [CI #38559750327](https://github.com/auraakart/Aaraaweb/actions/runs/38559750327), develop merge `02d76a35c2826977094b24bc68adda19fc1bf43a`.

An already-issued V5.5.7 HMAC-authenticated **claim is not a build permit**. This slice adds `PartnerAndroidBuildWorkerConsumption`: one immutable consumption per claim (`UNIQUE(claimId)`), enforced with an append-only trigger. The database rechecks current commercial allocation, distribution approval, latest independently reviewed TEST revision, reservation version, source and lock digest, claim expiry and worker/actor identity. Consumption uses a **fresh short-lived, domain-separated** HMAC tuple bound to the claim, all society/license contexts, source and lock digest and the nominated TEST worker. The secret is not stored and consumption is default-disabled without the existing worker HMAC environment key. Claim and consumption must use separate signed nonces; the assertion domain prevents cross-stage replay.

The internal-only service `consume` reauthorizes `BEFORE_DISPATCH`, checks the existing claim and reviewed manifest again inside an allocated transaction, and records one consumption. No HTTP endpoint, native invocation, job queue or production authorization is created. It returns `CONSUMED_TEST_NO_EXECUTION`, `dispatchAllowed:false`, `executionStarted:false`, `artifactProduced:false`.

The `revalidateCompletion` method independently invokes a **fresh** `BEFORE_COMPLETION` checkpoint, checks the same worker/actor/claim/reservation/version, and returns `CURRENT_TEST_COMPLETION_AUTHORITY_ONLY`, `archiveVerified:false`. A successful completion checkpoint is **not** a signed APK or an accepted artifact.

This is a fail-closed staged authorization/control-plane implementation, **not actual worker integration or signed APK generation**. Outstanding: independently authenticated worker transport, verified source and pinned toolchain, image sanitization proof, ephemeral Flutter wrapper, native patch application, isolated and bounded process launch, actual test signing, archive/package/version/ABI verification and immutable artifact provenance. None may be inferred from a claimed or consumed record. Main demo APK, staging and main are untouched.
