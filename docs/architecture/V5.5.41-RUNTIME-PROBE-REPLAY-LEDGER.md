# V5.5.41 — Durable replay barrier for a read-only TEST runtime mTLS probe

Baseline: `develop` `63bce2b7c6e0b4be7f2a2998f52e519641f6cf0a` after V5.5.40 implementation #1346 and CI evidence #1347, both merged.

## Existing versus new trust boundaries

V5.5.14–15 already persists the original runner challenge and accepts one signed worker assertion, transactionally and without execution. V5.5.40 added a separate real TLS 1.3/mTLS **read-only** nonce-bound runtime evidence probe in disposable CI fixtures, but its fresh transport nonce was neither stored nor atomically consumed. V5.5.39 signed runtime claims also did not measure a real running container.

V5.5.41 persists one **hashed** runtime-transport nonce per previously accepted TEST challenge. It never stores the raw random nonce or private keys. It cannot be used to dispatch Flutter/Gradle or grant signer/artifact authority.

## Changes

- `packages/config/src/android-test-oci-runtime-transport.mjs` extends a successfully validated, immutable receipt with SHA-256 digests of the transport nonce, canonical signed runtime envelope, and observer signature, plus trusted pinned TLS server SPKI and local verification timestamp. This does not add remote process attestation.
- Prisma model `PartnerAndroidRunnerRuntimeProbe` and append-only PostgreSQL migration `20261015080000_v5541_runtime_probe_replay` enforce one row per acceptance, challenge, run ID, nonce digest, runtime-envelope digest and observer-signature digest, with FKs to accepted evidence and operator user. Native insert trigger rechecks accepted/challenge/worker/source/manifest identity, current approvals, actor, consumption, newest approved revision, expiry and active allocation under row locks. UPDATE/DELETE are prohibited.
- Internal-only `PartnerAndroidRunnerRuntimeProbeLedgerService.record(...,probeOnce)` runs a commercial checkpoint **before** invoking the injected internal fresh pinned-transport verifier. It then rechecks current TEST allocation/approval/reservation/acceptance in one transaction before inserting the digests. It is **not** exposed by any API controller; the caller must invoke `probePinnedTestOciRuntimeEvidence` with independently protected operator configuration, never partner-supplied endpoint/keys or untrusted receipt objects. Signature authenticity of the receipt cannot be inferred from booleans; this ledger grants no security authority beyond its own uniqueness.
- Vitest covers replay conflict, no-probe on revoked checkpoint, operator-key or worker mismatch, invalid/untrusted receipts, current approval checks, and persisted evidence minimality. The Node mTLS fixture checks the new digests. Auto-discovered structure check `check-v4.79.1.13-v5-runtime-replay.mjs` verifies migration/Prisma/source constraints. Protected CI remains authoritative.

## Safety and unresolved dependency

Ledger result `dbReplayBarrierVerified:true` means a **database uniqueness-backed recording of this read-only runtime probe**. It does **not** mean an independently provisioned worker or kernel was measured, or that a future execution challenge was consumed. `singleUseChallengeConsumed:false`, `runtimeImageAttested:false`, `remoteProcessMeasured:false`, `independentlyProvisionedWorkerVerified:false`, `buildExecutionAuthorized:false`, `artifactProduced:false`, `dispatchAllowed:false` remain mandatory.

Real TEST runner and registry ownership, separately held attestation keys, independently inspected OCI running digest/mount namespace and source filesystem flags, external mTLS operation, execution-specific durable challenge and Partner A/B signed builds/install isolation remain outstanding. Do not infer deployment readiness from green local fixtures. No CI YAML, staging, main, production rollout or hardware integration changes.

Next: run live operator-owned remote runtime image/mount attestation and provision an execution-specific persisted approval boundary **only after independently verified external identities**. V5.5 stays IN_PROGRESS; V5.6 is planned.
