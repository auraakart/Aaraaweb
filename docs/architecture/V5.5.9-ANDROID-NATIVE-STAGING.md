# V5.5.9 — Disposable TEST Android native staging

Baseline: V5.5.8 [PR #1299](https://github.com/auraakart/Aaraaweb/pull/1299), `develop` merge `3741c64131b9d4238d07390090b8114b9a96c3d3`. All protected PR checks passed. Release manifest now records the prior completion.

`materializeTestAndroidNativeWorkspace` composes the existing V5.5.4 resource-overlay materializer and V5.5.6 Kotlin patch planner, writing the **four reviewed native patch files** plus digest-checked icon and splash PNG bytes in a **new OS temporary directory**. No arbitrary caller-supplied root path is accepted. Writes have fixed or strictly validated Android paths; the helper refuses unexpected template inventory, mismatched independently expected SHA-256 template digests, foreign/stale version reservations, mutable TEST plans, injected native templates or tampered PNG bytes. Failure removes the temporary root. Successful callers **must** delete the directory in `finally`. A separate JSON staging inventory records input identity, pinned-template **assertion** digests and SHA/size of the four files. It explicitly records no executable worker, no generated Flutter wrapper, no real archive, and no verified signer.

**Security limitations:** Comparing independently supplied template SHA values only detects drift; it does **not** establish authenticity if supplied by a malicious client. Only an independently authenticated runner can provide the expected pinned Flutter template identity. The existing overlay checks PNG header/digest, not full image decoding/sanitization. Neither this module nor its tests performs source checkout, native platform generation, Gradle invocation, Dart build, test signing or artifact upload. Full Android styles/Android 12 splash integration must occur after a verified wrapper is produced.

Resident/Guard contract tests validate native bytes, digest inventory, package relocation, cleanup, forged templates, modified icon, stale reservation and source tampering. No API/Prisma schema, CI gate or main demo workflow changes; `staging` and `main` remain untouched.

Next: trusted worker connection with one-time execution consumption, separately pinned source/toolchain/native template, bounded disposable process invocation, actual APK/AAB archive/signature checks, completion reauthorization and immutable provenance.
