# V5.5.26 — Canonical TEST APK/AAB ZIP32 layout verification

Baseline: V5.5.25 PR #1316 merged to `develop` as `d3a80b9beda62c18807086ba0d76f6b728cd04db` after all protected checks passed.

The existing V5.5.23 CRC and central-directory scanner verified individual archive members but permitted bytes not represented by ZIP entries between the last local member and the central directory. This change requires every local byte to be accounted for by consecutive ZIP file records and their optional ZIP32 data descriptors, whose exact CRC and compressed/uncompressed sizes must agree with the central record. Hidden gaps, overlapping entries, malformed or truncated descriptors, and undeclared prefixes are rejected.

An APK with Signature Scheme v2/v3 can legitimately contain an APK Signing Block directly before the central directory. The scanner now accepts that region **only** when both 64-bit size fields and the fixed `APK Sig Block 42` footer match the exact gap. AAB files do not receive this exception. This is merely envelope/placement validation; forged framing does not prove any cryptographic signature, and the return flags `apkSigningBlockVerified:false`, `signerVerified:false`, `artifactPublished:false`, `dispatchAllowed:false` remain unchanged.

Regression cases use synthetic APK/AAB ZIP fixtures, including both signed and unsigned data descriptors, structurally framed APK Signing Blocks, hidden gaps, corrupted descriptors, and counterfeit signing block sizes/magic. These are not genuine signed Android binaries. V5.5.25's separately pinned `aapt2`/`apksigner` read-only verification remains mandatory; independently attested runner execution, real APK/AAB build, on-device co-installation and V5.6 acceptance are still pending.

Scope: code/tests/docs only, non-production; no cloud, external credentials, signing, live domain routing, staging or main promotion.
