# V5.4.12 — Nonproduction partner domain TXT verification

Scope: source-only, auditable, **inert** proof verification. Never interpret a DNS record, verified claim or Host header as authentication or an active route.

- `POST /api/v1/partners/:partnerId/domains/:claimId/verify` accepts a one-time 64-character lowercase hexadecimal claim token through an authenticated bearer session.
- Enable only in `NODE_ENV=test|development` with `AARAGATE_ENABLE_TEST_DOMAIN_VERIFICATION=true`. It cannot run in production.
- A live ACTIVE partner OWNER is checked twice, in separately committed DB transactions. A claim must remain PENDING and younger than seven days.
- Reservation increments a durable attempt counter before DNS; at most five attempts with sixty seconds between them. The token is compared with the SHA-256 registration digest using constant-time comparison.
- Resolver checks exact TXT at `_aaraagate-challenge.<registered-hostname>`, matching `aaraagate-domain-verification=<token>`. There is no URL fetch, redirect following, proxy-trust selection, or client-provided hostname.
- After DNS, recheck partner/owner/claim version and exactly one currently approved, unrevoked, active-period partner grant with matching approval/grant versions. Enforce maximumDomains across currently valid VERIFIED claims.
- VERIFIED records expire thirty days after proof. Audit event VERIFIED is immutable (existing V5.4.11 audit trigger). Do not activate routing, sessions, TLS, branded apps, or society operations on this status.
- Expired VERIFIED claims require a separately approved renewal/reissue workflow; this endpoint cannot re-verify a previously verified claim.

Acceptance: Prisma validation/migration, API lint/typecheck, focused proof tests, migration and full protected CI. No staging/main promotion. Next slices: hardened renewal/revocation and verification lifecycle; multi-host SSR/session isolation; partner onboarding; distribution approval.
