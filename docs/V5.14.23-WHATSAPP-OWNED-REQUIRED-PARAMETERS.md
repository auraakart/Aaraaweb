# V5.14.23 — WhatsApp template required-parameter own-property validation (development candidate)

Baseline: `develop` at `86d82fce7070e55e078454ffe931030220cfdb4b`, after accepted V5.14.20–V5.14.22 runtime validation and evidence reconciliation.

## Defect and bounded fix

`WhatsAppNotificationService.sendApprovedTemplate` checked required fields using ordinary property lookup. A runtime-created object inheriting `subjectName` or `subjectType` from its prototype could pass validation even though those fields were not own enumerable message data. A provider that serializes the object as JSON may therefore receive an incomplete approved-template payload.

Require every approved template's required parameter to be the message parameter object's **own** nonblank string value. Do not fall back to inherited properties or mutate the caller's object. Keep ordinary JSON parameter records, null-prototype maps with own values, approved templates, E.164 recipient checks, language selection and idempotency behavior unchanged.

## Validation and scope

Two negative regressions reject all-inherited or partly-inherited required values before the provider receives the event. A positive regression accepts a null-prototype map with own required values. Existing valid, idempotency, malformed payload, invalid template and scalar tests remain.
