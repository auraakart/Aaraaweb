# V5.11.3 — private document tenant isolation

Follow-on source work after occupancy mutation and scheduled worker boundaries. All eleven public DocumentsService entry points now use tenant transaction clients. Management detail/history, draft eligibility, publication, replacement, archiving and audit persistence remain within their selected transaction; private lookup/transition helpers require the caller's client.

## Preserved behavior and corrected boundaries

Preserve document audiences, status rules, property labels, version lineage, current/archived download behavior, knowledge ranking/tokens/excerpts, metadata normalization and immutable audit events. Draft property eligibility now executes alongside document/knowledge/event inserts. Publication/replacement retains row locks and conditional updates; archive retains conditional transitions and already-archived replay.

Owner-only and property-owner-only visibility now requires verified active ownership within effective dates and matching unit/building society. This preserves nonresident-owner access while denying unverified/expired and malformed ownership links. Document property parents must belong to the selected society for management and resident reads. Published lists evaluate ownership in their document SELECT rather than caching owner eligibility between separate statements. One duplicate ownership read is removed; no measured latency gain is claimed.

The controller still authorizes the document before private download signing. Storage key validation, metadata matching, upload scanning, infected-object removal, unconfigured-scanner failure and private signed intent behavior remain unchanged. No live provider acceptance or signed-object revocation-after-issuance guarantee is claimed.
