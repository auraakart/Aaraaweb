# V5.14.8 — Report CSV export isolation regression coverage (accepted source)

Baseline: accepted V5.14.7 develop `b81dea49b2747844533e08a8a9f745d1fc5a3684`. This **test-only** slice strengthens the report export security safety net without changing API runtime, data access, CSV formats, database schema, licensing, permissions or hosted configuration.

## New checks

- Reject audit CSV exports over the 5,000-row cap, without emitting a success audit event.
- Exercise two independent societies and require the read predicate and emitted audit event to retain the exact selected society ID. This is mocked behavior, not native cross-tenant PostgreSQL proof.
- Require invalid or excessive date windows to fail before any read or audit-write call.
- Pin the allowlisted privacy-safe audit CSV projection and the empty export contract.

These complement the existing explicit tenant predicates, audit-event filter validation, maintenance CSV bound tests, formula injection escaping, deterministic ordering and admin permission guards.

## Independent runtime conversion still required

`ReportsService`, `ReportsExportService`, and selected `ReportsAnalyticsService` SQL paths still use root Prisma access. Source conversions require transaction-local `withTenantContext` and usage of the supplied `tx`, with selected-role native PostgreSQL integration tests, exact inventory digest regeneration (`node services/api/scripts/tenant-access-inventory.mjs --write`) and summary synchronization (`node scripts/sync-tenant-access-summary.mjs --write`). The container cannot currently clone GitHub to run the complete inventory generator; do not weaken or handwave the canonical inventory CI contract. This test-only slice does not claim RLS activation or database tenant isolation closure.
