# V5.14.27 — Resident vehicle registration input quality

Baseline: V5.14.26 accepted on `develop`, exact source commit `681885e3fcca621accd6d434909d299f58c33474`.

## Defect
The Resident vehicle registration dialog checked only whether the entered plate was empty. Arbitrary punctuation or digits-only values could enter the society vehicle approval workflow. The backend canonicalizes spaces/hyphens before checking for duplicates but does not validate plate syntax.

## Bounded Resident change
For nonempty draft plates, apply the same case/space/hyphen normalization for **client-side validation only**. Require 4–16 ASCII letters/digits and at least one of each. Reject unsupported punctuation, all-digit and all-letter values without closing the dialog. Preserve the original approved request payload path, existing demo canonicalization, server-side authority, approval requirements and all form fields. This intentionally does not implement India-only plate format enforcement because BH-series and other formats exist.

## Regression and acceptance
Extend the existing vehicle/household widget test suite to reject punctuation and digits-only plates without posting a pending request, and accept a BH-series number that enters **pending** (not active) status. Keep the original compact-screen, keyboard, cancellation and TN registration test coverage.

Run protected Flutter analysis, selected/broad Resident and Guard validation plus repository required merge gates. API/database/schema/tenant access inventory, partner branding, staging/main and infrastructure are out of scope. Do not describe source acceptance as physical-device, live-operator or production acceptance.
