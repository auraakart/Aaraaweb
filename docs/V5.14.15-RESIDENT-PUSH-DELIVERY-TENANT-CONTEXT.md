# V5.14.15 — Resident push delivery tenant context (accepted on develop)

Baseline: accepted V5.14.14 on develop `b4c0dfd1af34799f7ffd8905529ea3ee85e75078`, 407 tenant-context call sites in the generated AST register.

## Scope and tenant boundary

Four remaining **resident delivery** access sites in `PushNotificationService.deliverResidentEvent` are converted from root Prisma to `withTenantContext(event.societyId, async tx => ...)` and the supplied transaction client: (1) active device token lookup, (2) active selected-society user membership lookup for branded app routing, (3) deactivation of a registration whose branded application fails authorization, and (4) deactivation of tokens permanently rejected by Firebase. The latter two updates now include both `societyId` and `userId` in addition to the device identifier, making selection explicit even before hosted RLS is enabled.

**Important:** Database transactions complete before Firebase network dispatch and before branded-app authorization performs its own independent scoped DB reads. The transition does not alter the established separate consumer-push path, globally unique consumer/device token transfer logic, cross-society push outbox leasing, push event payload contracts, 500-token batching, or transport retry behavior. Unknown partner application IDs remain fail-closed, never silently default to the shared Firebase application.

## Accepted regression and integration evidence

Added tests cover sequentially selected society lookup, root-client fallthrough rejection, completed database transaction before Firebase network dispatch, exact society/user scoping for invalid device revocation, authorized branded-membership routing and unauthorized branded-token revocation without delivery or unnecessary retry. The original Firebase multicast, durable outbox replay and foreign-society envelope test suites remain passing. The first test run found an expectation error: definitively unauthorized branded tokens are revoked and skipped (the service resolves) rather than triggering a retried routing failure. The test was corrected without production-code changes.

The canonical AST register was generated with `node services/api/scripts/tenant-access-inventory.mjs --write` and synchronized via `node scripts/sync-tenant-access-summary.mjs --write`. The count increased from 407 to **411** context calls. The temporary generator workflow was removed before PR review.
