# V5.14.26 — Resident emergency contact phone validation

Baseline: `develop` at `879a30a2c0dfc0f35f2df9397b37c181cc974542` (latest documented source: V5.14.25).

## Defect and bounded fix

The Resident emergency-contact dialog previously checked only whether the phone field had eight characters. Non-numeric strings or multiple plus signs could pass client validation and be submitted as emergency contacts, even though those values are not dialable.

Validate that the trimmed phone contains 8–15 ASCII digits and only standard formatting characters (one optional leading `+`, spaces, parentheses and hyphens). Keep existing national and international formatted numbers, optional relationship, priority, confirmation/retry semantics, backend authority, demo isolation and persisted phone formatting unchanged. The existing UI layout and primary theme remain untouched.

## Regression contract

Extend `apps/resident/test/household_modal_accessibility_test.dart` with a widget test verifying that alphabetic and double-plus phone values keep the dialog open and create no contact. A standard formatted `+91` number still saves unchanged. The earlier compact-dialog, large-text, keyboard and cancellation regressions remain.

Run pinned Resident analysis and targeted/broad widget tests in protected CI. This Flutter-only change does not modify Prisma/API/tenant inventory, RBAC, migrations, payment or backend behaviour.
