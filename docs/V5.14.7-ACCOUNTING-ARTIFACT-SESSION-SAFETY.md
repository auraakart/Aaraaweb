# V5.14.7 — Accounting artifact download session safety (candidate)

Baseline: accepted V5.14.6 develop `a0b44d6c362f3e1ff27c3689131199fd53d4cdf1` / tree `8a0d47773b97482ddadf4b423188c2715f0fd707`. Only Admin accounting export artifact downloads are changed; no API, database, schema, entitlement, or report-format changes.

## Root cause and fix

The Accounting exports page used direct `fetch` with the component's original bearer token to download `/accounting/exports/{jobId}/artifact`, without the shared Admin client session-lineage checks. A replaced login or society could receive old artifact bytes after a late response.

`downloadAdminBlob` now offers the narrow optional Accept union `text/csv` or `*/*`. Existing Reports and Migration CSV callers retain the CSV default. Accounting uses `*/*`, maintaining its existing content negotiation for CSV, Tally-friendly CSV and JSONL. The existing shared helper verifies the current login/society before fetching, after the response and after the body streams; allows one authorized 401 refresh; and refuses non-401 denial without replay. The Accounting UI retains server headers, exact bytes, fallback filename and error/busy behavior while sanitizing supplied filename characters.

## Regression evidence required

Four session tests cover JSONL/binary byte integrity and wildcard Accept, bounded 401 retry, society switch before response completion, and a 403 without replay. The V4.49 invariant is updated to verify shared, authenticated accounting transport and preserved CSV default. Protected Admin, API, Flutter, dependency, repository, browser/accessibility and build gates must pass before `develop` merge.

## Scope limits

This is unaccepted candidate source until protected CI completes; backend reporting tenant transaction conversion, notifications, remaining workforce boundaries, hosted RLS/grants, independent artifacts, devices, productionization and staging/main release work remain separate.
