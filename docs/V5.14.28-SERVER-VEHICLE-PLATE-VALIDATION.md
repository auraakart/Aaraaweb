# V5.14.28 — Enforce vehicle registration validation at the API boundary

Baseline: V5.14.27 merged to `develop` at `0032115bfa5c8bba55e9758fe0d64b63867e11f4`.

## Root cause
V5.14.27 added Resident-side format validation, but the API request and approval services previously normalized whitespace/hyphens only. A direct API caller could bypass client validation and enqueue malformed registrations.

## Change
Introduce one shared API canonicalizer and use it at both vehicle-add trust boundaries: resident change-request creation and approval/direct persistence. It strips spaces/hyphens, uppercases, and requires 4–16 ASCII letters/digits with at least one letter and one digit. BH-series formats remain accepted. Invalid values fail with a clear Bad Request message before database writes.

## Acceptance
Focused helper tests cover common state-format, BH-series and legacy registration examples, plus empty, all-digit, all-letter, punctuation and overlength inputs. Existing service tests continue to verify duplicate checks, society-scoped locking, owner/resident authorization, request approval, and historical-row reactivation.

No database/schema, client, tenant authorization, approval workflow, branding, staging/main, infrastructure, or productionization changes.
