# V5.4.9 Audited Partner Member Lifecycle (non-production)

- Reuses the existing bearer session and PartnerMembership, with a distinct partner commercial authority boundary.
- An active OWNER can invite an already-active user by opaque user ID, alter one existing member role or revoke an active member. Invites expire after seven days.
- Acceptance/decline is performed only by the invited identity; user status, inviter's current OWNER authority, partner status and no pre-existing active role are re-checked under a partner row lock. No email/phone address or recipient search API is exposed.
- Changing a role deactivates the previous role and activates the new role in one transaction. Multiple historical concurrent active roles fail closed for manual reconciliation; the last active owner cannot be changed or revoked.
- Revocation takes effect on the next per-request partner role validation; the existing read-only portal re-queries scope rather than caching commercial grants.
- Invitations record idempotency; changing its payload with the same key is rejected. A processed/expired invite cannot be accepted again. Security audit events are append-only at DB level.
- Not included: standalone partner login, account signup, email/SMS delivery, domain verification, paid license changes, production hosting or staging/main promotion.
- Verification: Prisma validate/generate, API typecheck/lint, dedicated V5.4.9 spec, migration smoke/PostgreSQL and protected CI before merge.
- Backward compatibility: changes add only tables/routes and do not alter society membership, resident/guard access, notifications, gate, SOS, payment rights or entitlements. Rollback is to remove new routes and keep the audit tables as retained evidence; destructive DB rollback is not authorized.

Source inventory: regenerated by the one-shot exact-repository inventory command and checked against the generated digest. The helper workflow retired itself in the same commit. Protected CI at this final feature-branch head remains the merge gate.
