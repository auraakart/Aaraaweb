# V5.14.36 — SOS acknowledgement deadline persistence

## Scope

This slice reconciles the Prisma data model with the already-applied SOS classification and routing-automation migrations, then makes manual responder assignment participate in the existing acknowledgement-deadline worker.

## Findings

- The database migrations add SOS category/severity, routing-policy rows, responder assignment/deadline fields, and nullable automated event attribution.
- The Prisma schema did not describe those persisted fields or the `SosRoutingPolicy` table. It also still described every SOS event as requiring a human actor, although scheduled automation writes actorless events with `actorSource='AUTOMATION'`.
- New SOS incidents can receive a responder and deadline from the database routing-policy trigger.
- Manual assignment previously appended an `ASSIGNED` event only. It did not update `assignedResponderUserId`, `assignedAt`, or `acknowledgeDueAt`, so the scheduled SOS escalation sweep could not see manually assigned active incidents.
- Manual responder validation checked active society membership but did not also reject a deactivated user account.

## Changes

- Align Prisma models and relations with the existing migration-owned SOS fields and routing-policy table; no duplicate migration is introduced.
- Make SOS event actor attribution optional in Prisma while preserving the migration's human/automation attribution model.
- Persist manual responder assignment in the incident row and derive its acknowledgement deadline from the active severity policy.
- Clear a prior automatic-escalation marker when an active incident is reassigned, allowing the new assignee's deadline to be evaluated independently.
- Validate both active membership and active user account before assignment.
- Preserve tenant transaction boundaries, append-only assignment event history, existing API route and permission contracts.
