# V5.14.14 — Notification tenant-local reads and gate evidence (accepted on develop)

Baseline: accepted V5.14.13 on develop `d72dfe11d7f53f3b98b7bf0952dd26c07447192c`. Canonical tenant-access source inventory reports 403 `withTenantContext` call sites.

## Bounded implementation

Society-scoped resident push registration readiness (`devicePushToken.count`), resident token deactivation on unregister (`devicePushToken.updateMany`), maintenance notification invoice-to-unit enrichment (`maintenanceInvoice.findFirst`), and gate notification fallback evidence persistence (`GateNotificationAttempt` INSERT/UPSERT) now use `PrismaService.withTenantContext(societyId, ...)` with **only the transaction client's delegate or `tx.$executeRaw`**. Existing society/user/invoice predicates, token normalization, notice/gate event routing, phone suffix privacy, and fail-closed missing-invoice behavior are retained. No Firebase network call is held open inside a database transaction.

This is a bounded notification slice: it does not blanket-scope `PushDeliveryOutboxService` because its retry queue spans platform consumers (null society) and resident notifications, or `PushNotificationService.registerConsumer` because globally unique device-token re-binding is intentional. Branded application authorization, Firebase token delivery batching and lifecycle writes, and global identity phone lookup require separate focused review. In particular, changing the globally unique resident `devicePushToken.upsert({ where: {token} })` registration would change cross-society token transfer semantics under future RLS; it is **not** altered here.

## Workforce review boundary

Targeted static inspection found that the core `workforce.service.ts`, `workforce-leave.service.ts`, `workforce-rating.service.ts`, `workforce-suspension.service.ts` and `society-workforce.service.ts` already route their society-scoped Prisma accesses through tenant transactions. Existing leave, payment, suspension, parent-scope and native PostgreSQL regression suites remain in protected CI. This observation does not certify every workforce-adjacent helper, external provider, or hosted RLS grant; no workforce runtime behavior is changed by this slice.

## Regression and acceptance
