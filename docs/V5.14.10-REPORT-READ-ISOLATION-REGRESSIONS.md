# V5.14.10 — Report read-isolation regression coverage (candidate)

Baseline: accepted V5.14.9 develop `f0fbfef843c69be53a4bdeccc92e3f55cee2bad0` / tree `5ac7214b32ff88c8e832f62e026587fe5f692049`.

## Problem and bounded correction

The Reports read service remains a separate runtime tenant-context conversion from accepted CSV exports. Existing unit tests checked single-society predicates, but did not sufficiently guard against stale society state being reused across successive requests for different societies.

This test-only slice adds three reproducible, selected-society regressions:

- Sequential summary calls for two societies preserve every aggregate's society predicate and enforce finance-amount redaction without FINANCE_READ.
- Access, Helpdesk, Maintenance, and Audit paginated feeds do not reuse a prior society's count, item scope or page offset.
- Security event count and page SQL bind the selected society independently when society contexts alternate, while retaining validated event filtering.

These are mocked tests: they verify observable service query contracts, not native restricted-role PostgreSQL behavior, hosted RLS, connection-pool transaction isolation, or the future use of `withTenantContext` for ReportsService reads.

## CI, inventory and follow-up
