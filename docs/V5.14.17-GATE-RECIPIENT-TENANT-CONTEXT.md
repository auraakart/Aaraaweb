# V5.14.17 — Gate-recipient selected-society transaction (candidate)

Baseline: V5.14.16 accepted on `develop` at `64910147d31200384f4769619d75bbcb44ae4f4c` (PRs #1590–#1591), with 412 canonical tenant-context calls.

## Bounded scope

`GateRecipientService.notificationRecipients` selects active, time-valid, gate-notification-enabled unit occupants through `PrismaService.withTenantContext(societyId, tx => ...)` instead of the unrestricted root Prisma model. The original `societyId` and `unitId` predicates, effective date filtering, active and notification preferences, primary-contact/escalation ordering, selected `userId` and `gateApprovalEnabled` projection, and public API remain unchanged. A missing or invalid tenant context fails closed; there is no root-client retry.

## Verification

The existing recipient tests are updated to provide a tenant transaction client and deny root reads. Additional regressions exercise sequential society A/B calls, same-unit cross-society exclusion, and errors during tenant-context setup without a global fallback. The V5.6.3 realtime cross-society routing regression remains applicable.

Canonical repository source inventory must be regenerated and checked with:
```sh
node services/api/scripts/tenant-access-inventory.mjs --write
node scripts/sync-tenant-access-summary.mjs --write
node services/api/scripts/tenant-access-inventory.mjs --check
node scripts/sync-tenant-access-summary.mjs
```
The expected count is 413 sites if this is the only new recognized runtime call. The number is an inventory count, not a runtime isolation certification.
