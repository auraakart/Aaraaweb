# V5.14.22 — WhatsApp scalar-input runtime validation (development candidate)

Baseline: V5.14.21 accepted on `develop` at `37f1ab33ce78bf46d0e0b8ce805d7f73448fb62e`.

## Scope and behavior
`WhatsAppNotificationService.sendApprovedTemplate` trims recipient and idempotency values and may trim an optional language code. The TypeScript signature does not protect runtime integrations or jobs from an undefined/non-string recipient/key or a non-string language value. Without a guard the service could throw a `TypeError` instead of an established controlled bad-request response.

Require recipient/idempotency-key strings before trimming, and require an optional non-null language code to be a string before normalizing. Keep existing E.164 format validation, nonblank keys, approved-template checks, valid payloads, null/omitted language fallback to `en`, and idempotent provider dispatch unchanged. Do not change WhatsApp provider configuration or approval policy.

Five new regression inputs assert bad-request response and that the provider is not called; existing valid-template and idempotent-repeat tests remain.
