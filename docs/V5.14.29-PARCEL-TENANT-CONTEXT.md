# V5.14.29 — Parcel tenant-context conversion

## Scope

Convert the parcel module's database operations to the existing `PrismaService.withTenantContext(societyId, ...)` boundary:

- Resident and gate-desk parcel lists.
- Parcel intake and its current-occupant validation.
- Pickup-code issue, verification, failed-attempt accounting and collection.
- Return-to-sender and parcel-event history.
- Current-occupant recipient lookup.
- Overdue parcel reminder eligibility, cooldown and evidence write.

## Preserved behavior

- All existing society, recipient, unit, parcel and event predicates remain in place.
- Intake still validates current occupancy under a row lock and commits parcel plus event evidence atomically.
- Pickup-code issuance keeps the society/parcel advisory lock, ten-minute expiry and five-attempt lockout.
- Failed pickup attempts still commit before the API returns the invalid-code error.
- Parcel pickup verifiers remain redacted from resident and desk list responses.
- Realtime resident notifications remain after the database transaction commits.
- Reminder overdue and cooldown rules remain unchanged.

## Isolation boundary

Every parcel-module query and mutation now runs through the selected tenant transaction client. No root Prisma query or standalone transaction remains in these three services. The transaction-local setting is not an RLS activation and does not replace the existing explicit society/parent predicates.

## Validation

- Existing parcel service tests were updated to provide only the selected transaction client.
- Recipient and reminder tests assert tenant context is established.
- Canonical API CI must pass the tenant-access inventory check, API lint/typecheck, parcel regression tests and PostgreSQL validation before merge.

No schema, API contract, permissions, notification payload, staging/main, productionization or infrastructure changes.
