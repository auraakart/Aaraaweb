# V5.11.5 — resident form lifecycle and compact accessibility

Continue the authorized Resident/Guard/Admin experience slice with the saved Emergency Contacts and Vehicles form priority. Preserve the existing theme, vehicle approval/removal rules and emergency-contact semantics.

## Changes

The vehicle registration method owned TextEditingControllers outside its dialog and disposed them when showDialog's result completed. That result can complete before the route's dismissal animation removes its TextFields. Move the controllers into a dedicated stateful dialog; capture the submitted payload before pop, and dispose controllers when the dialog State is actually removed. Cancel/system Back remains mutation-free. Empty registrations now keep the draft open with a field error instead of silently dismissing it.

Keep both forms vertically scrollable and use 16px horizontal modal margins for compact devices. Let selected dropdown labels determine their height at large text scale. Add keyboard Next/Done traversal, avoid autocorrect/suggestions on registration numbers, and expose emergency-contact validation as a screen-reader live region. Buttons, palette and the society-approval requirement remain intact.

## Acceptance

Seven new widget cases cover light/dark forms at 320px and 200% text with a simulated 280px keyboard inset; last field and submit actions must remain reachable. Capture four rendered PNGs using the existing SDK-font/visual artifact workflow. Additional cases cover focused Cancel/system Back dismissal and empty/valid vehicle submission retaining PENDING approval rather than activating a vehicle.

Local Flutter execution is unavailable in this workspace; protected Flutter analysis, focused/full widget tests and rendered artifact inspection are required before acceptance. API and performance code are unchanged by this slice. Simulated keyboard/text/semantics checks are not physical keyboard, TalkBack, Tamil voice, or native-device acceptance. Those remain on hold; broader Gate/Billing/Helpdesk, Admin consistency and multilingual acceptance stay separately tracked.
